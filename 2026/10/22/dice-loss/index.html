Dice Loss 公式、代码与常见错误：医学图像分割损失函数详解

发表于2026-10-22|更新于2026-10-22|医学影像

阅读约 7 分钟

前列腺、肿瘤、病灶在整张图里往往只占很小一部分。这时如果只看像素准确率，把所有像素都预测成背景也可能得到很高的分数，但分割结果毫无用处。Dice Loss 直接优化前景重叠，适合这种类别极度不平衡的场景；V-Net 原论文也正是为此引入了基于 Dice 系数的训练目标。

从 Dice 系数到 Dice Loss

取值 0 到 1，完全重合为 1，完全不相交为 0。它只关心前景，所以不会被海量背景像素稀释。

训练时需要可导，所以把硬标签的预测换成概率图，即 soft Dice：

其中 p 是网络输出的概率，g 是 0/1 的真实标签，smooth 是一个小常数。

flowchart TD
  A[网络输出 logits] --> B[Sigmoid 或 Softmax 得到概率 p]
  B --> C[与真实标签 g 逐元素相乘，求和得到交集]
  B --> D[p 求和]
  E[真实标签 g] --> C
  E --> F[g 求和]
  C --> G[分子：2 x 交集 + smooth]
  D --> H[分母：sum p + sum g + smooth]
  F --> H
  G --> I[Dice = 分子 / 分母]
  H --> I
  I --> J[Loss = 1 - Dice]

五个常见错误

1. 先阈值再求损失

阈值操作几乎处处梯度为零，网络无法通过它正常反向传播。训练时必须用连续概率；阈值化只用于评估。

2. 忘记 Sigmoid 或 Softmax

直接把 logits 放进公式，数值可以是负数或很大，Dice 的取值范围就失效了。如果使用的是已经内置激活的损失库，要确认网络最后一层有没有重复激活。

3. 批级与样本级混用

  • 样本级：每个病例算一个 Dice 再平均，每个病例权重相同，大病灶和小病灶一视同仁。
  • 批级：把整个 batch 拼起来算一次，大病灶主导结果，小病灶容易被忽略。

两种都合理，但要明确选择，并且验证指标的口径要和训练一致。

4. 空标注导致除零或梯度异常

很多切片或病例本身没有前景。分母为 0 时会得到 NaN；加了 smooth 后，如果预测也为空，Dice 等于 1，如果预测非空则接近 0，梯度会出现剧烈变化。

处理办法：保留 smooth，或者只在含前景的样本上计算 Dice，同时配合其他损失。

5. 多分类时把背景算进去

背景像素数量巨大，它的 Dice 几乎总是接近 1，会把平均值抬高，掩盖前景类别的真实表现。多分类时通常排除背景，或者对各类别分别记录。

它的局限，以及常见的搭配

  • 梯度不稳定：目标很小时，分母很小，梯度会很大，训练曲线抖动。
  • 只衡量重叠：对边界形状不敏感，需要 HD95 等指标 补充。
  • 不直接优化概率校准：Dice Loss 的目标是提高区域重叠，不能仅凭它的输出值判断置信度是否可靠。

实践中常用 Dice + 交叉熵 的组合：交叉熵提供稳定的逐像素梯度，Dice 负责缓解类别不平衡。更准确地说，nnU-Net v2 的默认普通类别任务使用等权 Dice + 交叉熵；如果采用区域标签训练，则使用 Dice + BCE。

小结

问题 选择
前景占比极小 Dice Loss 或 Dice + 交叉熵
训练不稳定 加大 smooth，或加入交叉熵
有大量空标注 保留 smooth，统计时单独处理空样本
多分类 排除背景，逐类记录 Dice

7 min read

A prostate, a tumour or a lesion often covers only a small part of the image — the foreground can be under 5% of the pixels. With plain per-pixel cross-entropy, a network that predicts everything as background already scores over 95% accuracy while producing a useless mask. Dice Loss is built for this extreme class imbalance, and it was popularised for 3D medical segmentation by V-Net.

From the Dice coefficient to Dice Loss

Let P be the predicted region and G the ground truth:

It runs from 0 to 1 — 1 for a perfect match, 0 for no overlap — and it ignores the huge background, so background cannot dilute it.

For training it must be differentiable, so hard predictions become probabilities: soft Dice.

p is the network’s probability, g the 0/1 ground truth, smooth a small constant.

flowchart TD
  A[Network logits] --> B[Sigmoid or softmax gives probability p]
  B --> C[Multiply with ground truth g and sum: intersection]
  B --> D[Sum of p]
  E[Ground truth g] --> C
  E --> F[Sum of g]
  C --> G[Numerator: 2 x intersection + smooth]
  D --> H[Denominator: sum p + sum g + smooth]
  F --> H
  G --> I[Dice = numerator / denominator]
  H --> I
  I --> J[Loss = 1 - Dice]

Five common mistakes

1. Thresholding before the loss

The gradient of a threshold is zero, so nothing is learned. Train on probabilities; threshold only for evaluation.

2. Forgetting sigmoid or softmax

Feeding raw logits into the formula gives negative or huge values and the Dice range stops holding. If you use a library loss with a built-in activation, check the last layer does not apply it twice.

3. Mixing batch-level and sample-level

  • Sample-level: one Dice per case, then average — every case counts equally, big lesion or small.
  • Batch-level: pool the whole batch and compute once — large lesions dominate and small ones are neglected.

Both are reasonable, but choose deliberately, and keep the validation metric consistent with training.

4. Empty masks

Many slices or cases have no foreground. A zero denominator gives NaN; with smooth, an empty prediction scores 1 while a non-empty one scores near 0, so the gradient swings sharply.

Keep smooth, or compute Dice only on samples that have foreground and add another loss.

5. Counting background in multi-class

Background has a huge pixel count and its Dice is almost always near 1, lifting the average and hiding how the foreground classes really do. Exclude it, or log each class separately.

Limits, and common pairings

  • Unstable gradients — with a tiny target the denominator is small and gradients get large, so the loss curve jitters.
  • Overlap only — it is insensitive to boundary shape; add HD95 and similar metrics.
  • Poor calibration — Dice Loss pushes outputs to 0 or 1, so the probabilities are no longer trustworthy.

In practice Dice + cross-entropy is common: cross-entropy supplies stable per-pixel gradients and Dice counters the imbalance. nnU-Net uses this combination by default.

Summary

Situation Choice
Tiny foreground Dice Loss or Dice + cross-entropy
Unstable training Larger smooth, or add cross-entropy
Many empty masks Keep smooth; report empty cases separately
Multi-class Exclude background, log Dice per class

For the network side, continue with U-Net explained; for a full model that uses these ideas, see the MM-UNet overview.
