BatchNorm 超详细入门：手算公式、训练与推理差异，以及 BN/LN/IN/GN 怎么选

发表于2026-10-25|更新于2026-10-25|基础概念

阅读约 24 分钟 · 包含手算、代码和排错清单

BatchNorm 常被缩写成 BN。你会在网络代码里反复看到这样的组合：

它看起来像一个无关紧要的“标准配件”，实际上同时影响训练速度、学习率、批大小、验证结果和模型部署。ResNet 中几乎每个卷积后都有 BN；如果不理解它的训练与推理差异，很容易遇到“训练很好、验证突然变差”“同一张图每次预测不一样”之类的问题。

先给出一句最直观的解释：

BatchNorm 会在每个通道内，把一批数据拉回到较稳定的数值尺度，再允许模型用可学习参数把它缩放和平移到最合适的位置。

阅读前：什么叫“归一化”

假设两门考试的难度不同：

只看原始分数，95 好像远强于 70；但如果还知道每场考试的均值和分数波动，就能判断“你比同场平均水平高多少”。归一化做的是类似的事：不只看原值，而是看它相对所在分布的位置。

神经网络各层输出的尺度会随参数更新不断改变。某层今天输出大多在 [-1, 1]，训练几步后可能变成 [-20, 20]。后面的层就像不断面对评分标准变化的试卷，优化会更困难。BN 通过动态标准化，帮助数值保持在较可控的范围。

论文名片

  • 论文： Batch Normalization: Accelerating Deep Network Training by Reducing Internal Covariate Shift
  • 作者： Sergey Ioffe、Christian Szegedy
  • 会议： ICML 2015
  • 论文地址： arXiv:1502.03167

原论文用“减少内部协变量偏移”解释 BN。后续研究发现，这不是完整答案；BN 对优化曲面和梯度的平滑作用可能更关键。本文会把“它怎么算”“代码怎么表现”和“为什么可能有效”分开讲，避免把假说当成公式本身。

一、先用四个数字手算一次

暂时忘掉图片和通道，假设一个小批次里只有四个数：

$$x = [\ 1,\ 3,\ 5,\ 7\ ]$$

第 1 步：计算均值

$$\mu = \frac{1 + 3 + 5 + 7}{4} = 4$$

均值表示这一组数据的中心。

第 2 步：计算方差

先看每个数离均值多远，再平方、求平均：

$$(1-4)^2 = 9 \qquad (3-4)^2 = 1 \qquad (5-4)^2 = 1 \qquad (7-4)^2 = 9$$

$$\sigma^2 = \frac{9 + 1 + 1 + 9}{4} = 5$$

方差表示数据分散程度。平方是为了不让正负偏差互相抵消。

第 3 步：标准化

$$\hat{x} = \frac{x - \mu}{\sqrt{\sigma^2 + \epsilon}}$$

暂时忽略很小的 $\epsilon$，标准差是 $\sqrt{5} \approx 2.236$：

$$\begin{aligned}
1 &\longrightarrow (1-4)/2.236 \approx -1.342 \cr
3 &\longrightarrow (3-4)/2.236 \approx -0.447 \cr
5 &\longrightarrow (5-4)/2.236 \approx +0.447 \cr
7 &\longrightarrow (7-4)/2.236 \approx +1.342
\end{aligned}$$

标准化后的四个数均值约为 0，方差约为 1。

第 4 步：可学习地缩放和平移

BN 不会停在 $\hat{x}$，还会计算：

$$y = \gamma \hat{x} + \beta$$

假设模型学到 $\gamma = 2$、$\beta = 0.5$：

$$\begin{aligned}
-1.342 &\longrightarrow -2.184 \cr
-0.447 &\longrightarrow -0.394 \cr
+0.447 &\longrightarrow +1.394 \cr
+1.342 &\longrightarrow +3.184
\end{aligned}$$

$\gamma$ 和 $\beta$ 不是人工指定的超参数，而是像卷积核一样通过反向传播学习的参数。

为什么标准化之后还要“改回去”

如果所有特征都被强制固定为零均值、单位方差，可能限制网络表达能力。$\gamma$ 和 $\beta$ 给模型选择权：

  • $\gamma$ 控制拉伸或压缩；
  • $\beta$ 控制整体左移或右移。

例如模型若发现原来的分布最合适，可以学习到恰当的 $\gamma$、$\beta$，在给定统计量下恢复所需的尺度与位置。因此 BN 不是简单粗暴地把所有层永久锁死在同一个分布上。

二、图片上的 BN 到底对哪些数字求均值

卷积层输出通常是四维张量：

$$(N,\ C,\ H,\ W)$$

维度 含义 例子
$N$ batch 中的样本数 一次送入 8 张图
$C$ 通道数 64 张特征图
$H$ 特征图高度 56
$W$ 特征图宽度 56

BatchNorm2d(C) 为每一个通道单独计算统计量。对通道 c，它收集：

也就是所有样本在该通道的全部空间位置，共 $N \times H \times W$ 个值。

对每个通道 $c$：

$$\mu_c = \frac{1}{NHW} \sum_{n,h,w} x_{n,c,h,w} \qquad \sigma_c^2 = \frac{1}{NHW} \sum_{n,h,w} \left( x_{n,c,h,w} - \mu_c \right)^2$$

$$\hat x_{n,c,h,w} = \frac{x_{n,c,h,w} - \mu_c}{\sqrt{\sigma_c^2 + \epsilon}} \qquad y_{n,c,h,w} = \gamma_c \hat x_{n,c,h,w} + \beta_c$$

因此有 64 个通道时，会得到 64 个均值、64 个方差、64 个 $\gamma$ 和 64 个 $\beta$。BN 不会把 64 个通道混在一起计算一个总均值。

一个小尺寸例子

假设输入是 (N=2, C=3, H=2, W=2)，每个通道参与统计的数字个数是：

$$N \times H \times W = 2 \times 2 \times 2 = 8$$

三个通道各自用 8 个数计算各自的均值和方差。这个例子也解释了为什么 BN 名字里虽然有 “Batch”，在卷积网络中统计样本数不只是 $N$，还包括 $H \times W$ 个空间位置。

图中每个小方格代表一张 $H \times W$ 特征图。横向是 batch 维 $N$，纵向是通道维 $C$；有颜色的格子表示一起计算均值和方差的范围。

三、公式里每个符号到底是什么

$$\hat{x} = \frac{x - \mu}{\sqrt{\sigma^2 + \epsilon}} \qquad y = \gamma \hat{x} + \beta$$

符号 来源 是否学习 作用
$x$ 上一层输出 否 待归一化的输入
$\mu$ 当前 batch 或运行统计 否 找到分布中心
$\sigma^2$ 当前 batch 或运行统计 否 衡量分布宽度
$\epsilon$ 人工设定，常为 1e-5 否 防止方差太小导致除零
$\gamma$ BN 参数 是 每通道缩放
$\beta$ BN 参数 是 每通道平移

一个有 $C$ 个通道的 BN 通常有：

  • 可学习参数： $C$ 个 $\gamma$ 加 $C$ 个 $\beta$，合计 $2C$ 个；
  • 状态缓冲量： $C$ 个 running_mean 和 $C$ 个 running_var。

running_mean 和 running_var 会保存到模型文件里，但它们不是通过梯度下降学习的，所以通常不计入 trainable parameters。

四、最关键的知识：训练和推理走两条不同路线

很多 BN bug 都来自没有真正理解这一节。

1. 训练模式：使用当前 mini-batch

当模型处于 model.train() 时：

  1. 用当前 batch 的数据计算 $\mu_{\mathrm{batch}}$ 和 $\sigma^2_{\mathrm{batch}}$；
  2. 用它们归一化当前 batch；
  3. 同时更新 running_mean 和 running_var，供以后推理使用。

PyTorch 默认的更新形式可理解为：

$$\begin{aligned}
\mathrm{running\ mean} &\leftarrow (1 - m)\ \mathrm{running\ mean} + m\ \mu_{\mathrm{batch}} \cr
\mathrm{running\ var} &\leftarrow (1 - m)\ \mathrm{running\ var} + m\ \sigma^2_{\mathrm{batch}}
\end{aligned}$$

其中 $m$ 就是 PyTorch 的 momentum。

PyTorch BatchNorm 默认 momentum=0.1。注意这里的 momentum 写法与一些优化器或其他框架的定义可能相反，阅读代码时要看具体公式。

2. 推理模式：使用训练时积累的运行统计量

当模型处于 model.eval() 时：

$$\hat{x} = \frac{x - \mathrm{running\ mean}}{\sqrt{\mathrm{running\ var} + \epsilon}}$$

当前输入中有哪些其他样本，不再影响统计量。这样同一张图单独预测或与别的图一起预测时，输出应保持一致（忽略数值舍入等因素）。

3. 为什么推理不能继续依赖当前 batch

部署时可能一次只来一张图片，也可能不同请求被任意组合。如果继续用当前 batch：

  • 同一张图片会因为“同批还有谁”而得到不同结果；
  • batch 很小时，均值和方差噪声更大；
  • 线上数据顺序和 batch 组成会意外改变预测。

对 BatchNorm2d 来说，即使 N=1，它通常仍可在 H×W 位置上计算统计量，所以不能简单说输出一定变成常数；真正的问题是这些统计量变成依赖当前单个样本的、与训练运行统计不同的量。

4. model.eval() 不等于“不计算梯度”

这是另一个高频误区：

验证和推理通常两者都要。eval() 本身不会关闭自动求导；no_grad() 也不会自动让 BN 改用运行统计。

五、为什么 BN 往往能让训练更容易

1. 原论文的解释：减少内部协变量偏移

训练时，前面层的参数不断变化，后面层看到的输入分布也随之变化。原论文认为 BN 稳定了中间分布，使后层不必反复追赶。

这个解释很有直觉吸引力，但后续实验表明，即使人为扰乱 BN 后的分布，BN 仍可能加速训练。因此“分布稳定”不能完整解释所有效果。

2. 后续更常见的解释：让优化更平滑

Santurkar 等人在 How Does Batch Normalization Help Optimization? 中指出，BN 会让损失和梯度对参数变化更平滑。直观地说：

因此训练通常对初始化更宽容，也常能使用更大的学习率。不过“学习率一定能放大十倍”不是普遍定律，仍需结合网络、优化器和任务验证。

3. BN 带来与 batch 相关的噪声

同一张图片与不同样本组成 batch 时，$\mu_{\mathrm{batch}}$ 和 $\sigma^2_{\mathrm{batch}}$ 略有不同，它归一化后的值也会略变。这种随机扰动有时产生类似正则化的效果。

这不等于 BN 可以完全替代 Dropout。二者机制不同，是否同时使用要看任务与实验。

六、小 batch 为什么让 BN 难受

假设要估计全班学生的平均身高：

BN 也是如此。batch 较小时：

  • $\mu_{\mathrm{batch}}$ 和 $\sigma^2_{\mathrm{batch}}$ 的波动更大；
  • 每次归一化注入更强噪声；
  • 训练时看到的 batch 统计与推理时使用的 running 统计更容易不匹配。

“多小算小”没有脱离任务的固定答案。对普通 2D 分类，单卡每层有较多样本时 BN 常表现很好；对检测、分割和 3D 医学影像，即使 N=1 或 2，显存也可能已经用满，此时往往应认真比较 GroupNorm 或 InstanceNorm。

多 GPU 不等于 BN 看到了全局 batch

普通 nn.BatchNorm2d 在每张 GPU 上独立统计。例如总 batch 为 32、使用 8 张卡时，每张卡可能只用 4 个样本估计统计量。

nn.SyncBatchNorm 会跨进程同步统计量，使 BN 看到更大的有效 batch，但代价是通信开销增加。

梯度累积不能自动增大 BN 的统计 batch

假设每次前向只放 2 个样本，累计 8 次梯度后再更新参数。优化器等效 batch 也许是 16，但 BN 每次仍只用当前 2 个样本计算均值和方差。

这是医学影像训练里非常容易忽略的一点。

七、BN、LN、IN、GN 到底差在哪

它们大多都在做“减均值、除标准差、再缩放平移”，根本差异是：哪些元素被放在一起计算均值和方差。

BatchNorm（BN）

  • 依赖 batch；
  • 训练与推理行为不同；
  • 大 batch 的 CNN 分类中非常常见。

LayerNorm（LN）

对每个样本独立，在指定特征维度上统计。在 Transformer 中通常对每个 token 的隐藏维度归一化；若直接用于 NCHW 图像并归一化 C×H×W，则会把单个样本的通道和空间范围一起考虑。

  • 不依赖 batch；
  • 训练与推理一致；
  • Transformer 和序列模型的标准选择。

InstanceNorm（IN）

  • 每张图单独处理；
  • 会削弱每个实例自己的整体亮度、对比度等“风格”信息；
  • 常用于风格迁移、图像生成，也常见于 3D 医学分割。

GroupNorm（GN）

把通道分成若干组，对每个样本的组内通道和空间位置统计：

  • 不依赖 batch；
  • 小 batch 时通常比 BN 稳定；
  • 检测、分割和显存紧张场景常用。

快速选择表

场景 常见起点 原因
2D 图像分类，单卡 batch 较大 BatchNorm 成熟、高效、预训练模型丰富
目标检测 / 分割，单卡 batch 很小 GroupNorm 不依赖 batch 组成
3D CT/MRI，batch 常为 1–2 InstanceNorm 或 GroupNorm 显存限制下比 BN 稳定
Transformer LayerNorm 对每个 token 独立，不依赖 batch
风格迁移 InstanceNorm 弱化单图对比度与风格统计

这只是可靠的起点，不是不可违反的规则。最终选择应通过验证集和训练稳定性决定。

九、BN 与卷积怎么搭配

1. 为什么卷积常写 bias=False

卷积输出可简写为：

$$z = \mathrm{Conv}(x) + b$$

训练时 BN 紧接着减去 batch 均值。对所有空间位置都一样的卷积偏置 $b$ 会同时出现在 $z$ 和 $\mathbb{E}[z]$ 中，减均值时被抵消；之后 BN 自己还有 $\beta$ 负责平移。因此经典的 Conv → BN 结构常写：

2. Conv-BN-ReLU 还是 BN-ReLU-Conv

  • ResNet v1 常用 Conv → BN → ReLU；
  • 预激活 ResNet v2 使用 BN → ReLU → Conv；
  • 不能脱离整个网络结构，只把顺序随意调换并期待预训练权重仍兼容。

3. 部署时可以融合 Conv 与 BN

推理时 running mean/var、$\gamma$、$\beta$ 都是固定的，因此可把 BN 的线性变换折叠进前面的卷积权重和偏置，减少一个运行时算子。许多推理引擎会自动做 Conv-BN fusion。

这只适用于推理态的固定统计，训练时 BN 依赖当前 batch，不能用同样方式永久折叠。

十一、排查 BN 问题的实用清单

症状 1：训练指标很好，验证指标异常差

依次检查：

  1. 验证前是否调用 model.eval()；
  2. 验证结束后继续训练时是否恢复 model.train()；
  3. 训练 batch 是否太小，running 统计是否可靠；
  4. 训练与验证的数据预处理是否一致；
  5. 保存和加载时是否遗漏 buffer（正常 state_dict 会包含）。

症状 2：同一张图片单独预测与成批预测结果不同

最先检查模型是不是仍在 train 模式。若已是 eval，再排查随机数据增强、Dropout、非确定性算子和预处理差异。

症状 3：微调后预训练骨干性能崩掉

可能是虽然冻结了参数，BN running 统计仍被小数据集改写。检查各 BN 模块的 .training 属性。

症状 4：batch size 改小后训练明显不稳定

可比较以下方案：

  • 使用 GroupNorm 或 InstanceNorm；
  • 使用 SyncBatchNorm 增大跨卡统计范围；
  • 冻结预训练 BN 的运行统计；
  • 如果任务允许，增大单次前向 batch。

仅靠梯度累积不会让 BN 看到更多样本。

症状 5：模型只有一个数时 BN 报错

训练模式下，每通道可用于计算方差的元素必须足够。例如形状接近 (N=1, C, H=1, W=1) 时，每通道只有一个值，BN 无法得到有意义的 batch 方差，PyTorch 会报错。可增大统计范围、改用其他归一化，或调整结构。

十二、几个容易被忽略的实现细节

eps 是干什么的

如果一个通道里的值几乎完全相同，方差接近 0：

$$\frac{x - \mu}{\sqrt{\sigma^2}}$$

可能除以 0 或产生巨大数值。加入一个很小的 $\epsilon$ 保证数值稳定。通常保持框架默认值即可，除非有混合精度或特定数值问题需要调试。

PyTorch 的方差估计细节

PyTorch 文档说明，训练前向中用于归一化的 batch 方差采用有偏估计，而写入 running variance 时使用无偏估计。初学阶段不必手动复现这个细节，但它解释了为什么自己用几行代码手算时，结果可能与框架有轻微差异。

track_running_stats=False 不是普通默认用法

关闭它后，BN 不保存 running mean/var，评估时也会使用当前输入的统计量。这会让结果重新依赖当前 batch。只有明确知道这种行为正是自己所需时才使用。

混合精度下的统计

低精度训练对方差等统计更敏感。成熟的自动混合精度流程通常会为归一化保留合适精度，但自定义算子或手写归一化时要特别小心数值溢出和下溢。

十三、三道自测题

1. 一个 BatchNorm2d 输入为 (8

每个通道使用 $N \times H \times W = 8 \times 32 \times 32 = 8192$ 个值。64 个通道分别计算各自的统计量。

2. model.eval() 和 torch.no_grad() 有什么区别？

model.eval() 改变 BN 与 Dropout 等层的行为；torch.no_grad() 关闭梯度记录。标准推理通常两者都用。

3. 梯度累积把等效 batch 从 2 变成 16，BN 的统计 batch 也变成 16 吗？

不会。BN 在每次前向时就计算统计量，每次仍只看到 2 个样本。梯度累积只推迟优化器更新。

最后用一张清单复习

  • BN 的核心计算是“减均值、除标准差、再乘 $\gamma$ 加 $\beta$”。
  • 卷积 BN 按通道统计，每个通道跨 $N \times H \times W$ 求均值与方差。
  • $\gamma$、$\beta$ 是可学习参数；running_mean 与 running_var 是随训练更新并保存的状态。
  • train 模式使用当前 batch 统计并更新 running 统计；eval 模式读取 running 统计。
  • model.eval() 与 torch.no_grad() 解决的是两件不同的事。
  • BN 依赖 batch；batch 太小时，GroupNorm 或 InstanceNorm 往往更稳。
  • 梯度累积不能增大单次前向中的 BN 统计范围。
  • 冻结参数不等于冻结 BN 的 running 统计。
  • Conv → BN 时，卷积通常使用 bias=False。

About 24 minutes · Includes calculations, code and a troubleshooting checklist

Batch Normalization is usually shortened to BatchNorm or BN. You will repeatedly see this sequence in network code:

It may look like an unimportant standard component, but it affects training speed, learning rate, batch size, validation results and deployment. Almost every convolution in ResNet is followed by BN. If you do not understand how BN differs between training and inference, you can easily encounter problems such as “training is excellent but validation suddenly collapses” or “the same image receives different predictions”.

The most intuitive summary is:

Within each channel, BatchNorm brings a batch of values back to a more stable numerical scale, then lets the model learn the most useful scale and offset.

Before reading: what is normalisation?

Imagine two examinations with different difficulty:

Looking only at raw scores, 95 appears much better than 70. Once you know each exam’s mean and spread, you can instead ask how far above the corresponding average each score lies. Normalisation does something similar: it considers not only a raw value, but also its position within a distribution.

The scale of every neural-network layer changes as parameters are updated. A layer may output mostly within [-1, 1] today and move to [-20, 20] after several optimisation steps. Later layers then face a continuously changing scoring system. BN dynamically standardises these values and helps keep them within a more manageable range.

Paper at a glance

  • Paper: Batch Normalization: Accelerating Deep Network Training by Reducing Internal Covariate Shift
  • Authors: Sergey Ioffe and Christian Szegedy
  • Venue: ICML 2015
  • Paper: arXiv:1502.03167

The original paper explained BN as reducing “internal covariate shift”. Later work showed that this is not a complete account; smoothing the optimisation landscape and gradients may be more important. This article separates what BN computes, how code behaves and why it may work so that a hypothesis is not mistaken for the definition.

1. Calculate BN by hand with four numbers

Temporarily ignore images and channels. Suppose a mini-batch contains only four values:

$$x=[\ 1,\ 3,\ 5,\ 7\ ]$$

Step 1: calculate the mean

$$\mu=\frac{1+3+5+7}{4}=4$$

The mean is the centre of this group of values.

Step 2: calculate the variance

Measure each value’s distance from the mean, square it and average the results:

$$(1-4)^2=9 \qquad (3-4)^2=1 \qquad (5-4)^2=1 \qquad (7-4)^2=9$$

$$\sigma^2=\frac{9+1+1+9}{4}=5$$

Variance measures how spread out the values are. Squaring prevents positive and negative deviations from cancelling each other.

Step 3: standardise

$$\hat{x}=\frac{x-\mu}{\sqrt{\sigma^2+\epsilon}}$$

Ignore the tiny $epsilon$ for the moment. The standard deviation is $\sqrt{5}\approx2.236$:

$$\begin{aligned}
1 &\longrightarrow (1-4)/2.236 \approx -1.342 \cr
3 &\longrightarrow (3-4)/2.236 \approx -0.447 \cr
5 &\longrightarrow (5-4)/2.236 \approx +0.447 \cr
7 &\longrightarrow (7-4)/2.236 \approx +1.342
\end{aligned}$$

The standardised values have a mean close to zero and variance close to one.

Step 4: learn a scale and shift

BN does not stop at $\hat{x}$. It computes:

$$y=\gamma\hat{x}+\beta$$

Suppose the model learns $\gamma=2$ and $\beta=0.5$:

$$\begin{aligned}
-1.342 &\longrightarrow -2.184 \cr
-0.447 &\longrightarrow -0.394 \cr
+0.447 &\longrightarrow +1.394 \cr
+1.342 &\longrightarrow +3.184
\end{aligned}$$

$\gamma$ and $\beta$ are not manually chosen hyperparameters. They are model parameters learned by backpropagation just like convolutional kernels.

Why change the values again after standardisation?

Forcing every feature permanently to zero mean and unit variance could restrict what the network can represent. $\gamma$ and $\beta$ give it a choice:

  • $\gamma$ stretches or compresses the values;
  • $\beta$ shifts the complete distribution left or right.

If the model discovers that the original distribution was useful, it can learn suitable values of $\gamma$ and $\beta$ to restore the required scale and position under the current statistics. BN therefore does not permanently lock all layers to one fixed distribution.

2. Which values does BN average in an image tensor?

A convolution normally outputs a four-dimensional tensor:

$$(N,\ C,\ H,\ W)$$

Dimension Meaning Example
$N$ samples in the batch 8 images
$C$ channels 64 feature maps
$H$ feature-map height 56
$W$ feature-map width 56

BatchNorm2d(C) computes statistics separately for every channel. For channel c, it collects:

That is every spatial position in this channel from every sample: $N\times H\times W$ values.

For each channel $c$:

$$\mu_c=\frac{1}{NHW}\sum_{n,h,w}x_{n,c,h,w} \qquad \sigma_c^2=\frac{1}{NHW}\sum_{n,h,w}(x_{n,c,h,w}-\mu_c)^2$$

$$\hat x_{n,c,h,w}=\frac{x_{n,c,h,w}-\mu_c}{\sqrt{\sigma_c^2+\epsilon}} \qquad y_{n,c,h,w}=\gamma_c\hat x_{n,c,h,w}+\beta_c$$

With 64 channels, BN therefore has 64 means, 64 variances, 64 $\gamma$ values and 64 $\beta$ values. It does not mix all 64 channels into one global mean.

A small example

Suppose the input has shape (N=2, C=3, H=2, W=2). The number of values used for each channel is:

$$N\times H\times W=2\times2\times2=8$$

Each of the three channels uses its own eight values to estimate its own mean and variance. This also explains why, despite the word “Batch”, convolutional BN uses not only $N$ samples but also $H\times W$ spatial positions.

Each small square represents one $H\times W$ feature map. The horizontal axis is the batch dimension $N$, the vertical axis the channel dimension $C$, and coloured squares are normalised together.

3. What does every symbol in the formula mean?

$$\hat{x}=\frac{x-\mu}{\sqrt{\sigma^2+\epsilon}} \qquad y=\gamma\hat{x}+\beta$$

Symbol Source Learned? Purpose
$x$ previous layer no input to normalise
$\mu$ current batch or running statistics no centre of the distribution
$\sigma^2$ current batch or running statistics no width of the distribution
$\epsilon$ manually set, often 1e-5 no prevents division by zero when variance is tiny
$\gamma$ BN parameter yes per-channel scale
$\beta$ BN parameter yes per-channel shift

A BN layer with $C$ channels normally has:

  • learnable parameters: $C$ values of $\gamma$ and $C$ values of $\beta$, or $2C$ in total;
  • state buffers: $C$ values in running_mean and $C$ values in running_var.

running_mean and running_var are saved in the model file, but they are not learned by gradient descent and are therefore not usually counted as trainable parameters.

4. The most important fact: training and inference take different routes

Many BN bugs come from not fully understanding this section.

4.1 Training mode uses the current mini-batch

When the model is in model.train() mode, BN:

  1. calculates $\mu_{\mathrm{batch}}$ and $\sigma^2_{\mathrm{batch}}$ from the current batch;
  2. uses them to normalise the current batch;
  3. updates running_mean and running_var for future inference.

PyTorch’s default update can be understood as:

$$\begin{aligned}
\mathrm{running\ mean}&\leftarrow(1-m)\ \mathrm{running\ mean}+m\ \mu_{\mathrm{batch}} \cr
\mathrm{running\ var}&\leftarrow(1-m)\ \mathrm{running\ var}+m\ \sigma^2_{\mathrm{batch}}
\end{aligned}$$

Here $m$ is PyTorch’s momentum, which defaults to 0.1 for BatchNorm. Be careful: some optimisers and frameworks define momentum in the opposite direction, so always check the actual formula.

4.2 Evaluation mode uses accumulated running statistics

When the model is in model.eval() mode:

$$\hat{x}=\frac{x-\mathrm{running\ mean}}{\sqrt{\mathrm{running\ var}+\epsilon}}$$

Other samples in the current input no longer change the statistics. The same image should therefore produce the same output whether it is predicted alone or alongside other images, apart from numerical round-off and similar effects.

4.3 Why not keep using the current batch during inference?

Deployment may receive one image at a time, and requests may be grouped arbitrarily. If inference continued to use the current batch:

  • the prediction for one image would depend on which other images happened to accompany it;
  • very small batches would give noisy mean and variance estimates;
  • the order and grouping of production requests could accidentally change predictions.

For BatchNorm2d, even when N=1 it can normally estimate statistics across the $H\times W$ positions, so the output does not necessarily become a constant. The real problem is that these statistics become specific to the current sample and different from the running statistics accumulated during training.

4.4 model.eval() does not mean “disable gradients”

This is another common misconception:

Validation and inference usually need both. eval() does not disable autograd, and no_grad() does not make BN use its running statistics.

5. Why does BN often make training easier?

5.1 The original explanation: less internal covariate shift

As early-layer parameters change during training, the input distribution seen by later layers changes too. The original paper argued that BN stabilises these intermediate distributions, so later layers do not need to keep chasing a moving target.

This explanation is intuitive, but later experiments showed that BN can still accelerate training even when the post-BN distribution is deliberately perturbed. Distribution stability therefore does not explain every benefit.

5.2 A common later explanation: smoother optimisation

Santurkar et al. argued in How Does Batch Normalization Help Optimization? that BN makes losses and gradients respond more smoothly to parameter changes. Intuitively:

Training is therefore often more tolerant of initialisation and may support a larger learning rate. “Always multiply the learning rate by ten” is not a universal rule; it still depends on the network, optimiser and task.

5.3 BN introduces batch-dependent noise

When the same image appears beside different samples, $\mu_{\mathrm{batch}}$ and $\sigma^2_{\mathrm{batch}}$ change slightly, so the normalised feature changes slightly too. This random disturbance can sometimes act like regularisation.

That does not mean BN completely replaces Dropout. Their mechanisms differ, and whether to use them together depends on the task and experiments.

6. Why are small batches difficult for BN?

Imagine estimating a whole class’s mean height:

BN faces the same issue. With a small batch:

  • $\mu_{\mathrm{batch}}$ and $\sigma^2_{\mathrm{batch}}$ fluctuate more;
  • every normalisation step injects stronger noise;
  • batch statistics during training are more likely to disagree with running statistics during inference.

There is no task-independent threshold for what counts as “small”. BN often works very well in 2D classification when each GPU holds many samples. Detection, segmentation and 3D medical imaging may already exhaust memory at N=1 or 2, in which case GroupNorm and InstanceNorm deserve serious comparison.

Multiple GPUs do not automatically give BN the global batch

Ordinary nn.BatchNorm2d estimates statistics independently on each GPU. A total batch of 32 across eight GPUs may therefore give each device only four samples for its local estimate.

nn.SyncBatchNorm synchronises statistics across processes so that BN sees a larger effective batch, at the cost of extra communication.

Gradient accumulation does not enlarge BN’s statistical batch

Suppose each forward pass contains two samples and gradients are accumulated for eight passes before the optimiser updates. The effective optimiser batch may be 16, but BN still estimates its mean and variance from only the current two samples each time.

This distinction is especially easy to miss in medical-image training.

7. What is the difference between BN, LN, IN and GN?

Most of these layers subtract a mean, divide by a standard deviation, then scale and shift. The fundamental difference is: which elements are grouped together to calculate the mean and variance?

BatchNorm (BN)

  • depends on the batch;
  • behaves differently during training and inference;
  • common in large-batch CNN classification.

LayerNorm (LN)

LayerNorm treats every sample independently and normalises over specified feature dimensions. A Transformer normally normalises the hidden dimension of each token. If LN is applied directly to an NCHW image tensor across C×H×W, it includes every channel and spatial position in that one sample.

  • does not depend on the batch;
  • has the same behaviour in training and inference;
  • standard for Transformers and sequence models.

InstanceNorm (IN)

  • processes every image independently;
  • suppresses each instance’s global brightness, contrast and other style statistics;
  • common in style transfer and image generation, and also in 3D medical segmentation.

GroupNorm (GN)

GroupNorm divides channels into groups and calculates statistics over the channels and spatial positions within each group of each sample:

  • does not depend on the batch;
  • is usually more stable than BN with small batches;
  • common in detection, segmentation and memory-constrained training.

A useful relationship between them

For convolutional features with GroupNorm:

GN can therefore be viewed as selecting a grouping scale between LN and IN. Exact learnable-parameter shapes and framework implementations may still differ, so this relationship does not mean pretrained weights can always be swapped mechanically.

Quick selection table

Scenario Common starting point Reason
2D image classification with a large per-GPU batch BatchNorm mature, efficient, abundant pretrained models
Detection or segmentation with a very small per-GPU batch GroupNorm independent of batch composition
3D CT/MRI with batch size 1–2 InstanceNorm or GroupNorm more stable than BN under memory limits
Transformer LayerNorm independent for each token and batch-free
Style transfer InstanceNorm reduces per-image contrast and style statistics

This is a reliable starting point, not an unbreakable rule. Use validation performance and training stability to make the final choice.

9. How should BN be combined with convolution?

9.1 Why is convolution often created with bias=False?

A convolutional output can be written as:

$$z=\mathrm{Conv}(x)+b$$

During training, the following BN subtracts the batch mean. The convolutional bias $b$, which is identical at every spatial position, appears in both $z$ and $\mathbb{E}[z]$ and is cancelled by centring. BN then has its own $\beta$ for shifting. A classic Conv → BN sequence therefore uses:

9.2 Conv-BN-ReLU or BN-ReLU-Conv?

  • ResNet v1 commonly uses Conv → BN → ReLU.
  • Pre-activation ResNet v2 uses BN → ReLU → Conv.
  • The order belongs to the complete architecture. Do not rearrange it casually and expect pretrained weights to remain compatible.

9.3 Conv and BN can be fused for deployment

At inference, running mean/variance, $\gamma$ and $\beta$ are fixed. BN’s linear transformation can therefore be folded into the preceding convolutional weights and bias, eliminating one runtime operator. Many inference engines perform Conv-BN fusion automatically.

This only applies to fixed inference statistics. During training, BN depends on the current batch and cannot be permanently folded in the same way.

11. A practical BN troubleshooting checklist

Symptom 1: training metrics are excellent but validation is unexpectedly poor

Check in this order:

  1. Was model.eval() called before validation?
  2. Was model.train() restored before training resumed?
  3. Is the training batch too small for reliable running statistics?
  4. Are training and validation preprocessing identical?
  5. Were buffers lost when saving or loading? A normal state_dict includes them.

Symptom 2: one image changes when predicted alone versus in a batch

First check whether the model is still in training mode. If it is already in evaluation mode, inspect random augmentation, Dropout, nondeterministic operations and preprocessing differences.

Symptom 3: a pretrained backbone collapses after fine-tuning

Its parameters may be frozen while small-dataset batches continue to overwrite BN running statistics. Inspect the .training property of every BN module.

Symptom 4: training becomes unstable after reducing batch size

Compare these options:

  • use GroupNorm or InstanceNorm;
  • use SyncBatchNorm to aggregate statistics across GPUs;
  • freeze running statistics in pretrained BN layers;
  • if the task allows it, increase the batch in each forward pass.

Gradient accumulation alone does not let BN see more samples.

Symptom 5: BN raises an error when each channel contains only one value

Training mode needs enough elements per channel to estimate variance. A shape close to (N=1, C, H=1, W=1) leaves only one value per channel, so PyTorch cannot obtain a meaningful batch variance. Increase the statistical range, choose another normalisation layer or change the architecture.

12. Implementation details that are easy to miss

What does eps do?

If every value in a channel is almost identical, its variance is close to zero:

$$\frac{x-\mu}{\sqrt{\sigma^2}}$$

could divide by zero or produce enormous values. A tiny $\epsilon$ keeps the computation numerically stable. The framework default is normally appropriate unless mixed precision or another specific numerical issue requires debugging.

PyTorch’s variance estimates

PyTorch documents that the batch variance used to normalise a training forward pass is the biased estimate, while the value stored in running variance uses the unbiased estimate. Beginners do not need to reproduce this detail manually, but it explains small differences between a handwritten calculation and the framework.

track_running_stats=False is not the normal default

With this option disabled, BN stores no running mean or variance and uses statistics from the current input even during evaluation. Predictions therefore depend on the current batch again. Use it only when that behaviour is deliberately required.

Statistics under mixed precision

Low-precision training makes variance and similar statistics more sensitive. Mature automatic mixed-precision pipelines normally retain an appropriate precision for normalisation, but custom kernels and handwritten normalisation need special care around overflow and underflow.

13. Three self-check questions

1. A BatchNorm2d input has shape (8

Each channel uses $N\times H\times W=8\times32\times32=8192$ values. The 64 channels estimate their statistics independently.

2. What is the difference between model.eval() and torch.no_grad()?

model.eval() changes the behaviour of layers such as BN and Dropout. torch.no_grad() disables gradient recording. Standard inference normally uses both.

3. Gradient accumulation changes the effective optimiser batch from 2 to 16. Does BN's statistical batch also become 16?

No. BN calculates statistics during each forward pass and still sees only two samples. Gradient accumulation only delays the optimiser update.

Final review checklist

  • BN subtracts a mean, divides by a standard deviation, then multiplies by $\gamma$ and adds $\beta$.
  • Convolutional BN calculates statistics per channel across $N\times H\times W$.
  • $\gamma$ and $\beta$ are learned parameters; running_mean and running_var are saved state updated during training.
  • Training mode uses current-batch statistics and updates running statistics; evaluation mode reads the running statistics.
  • model.eval() and torch.no_grad() solve different problems.
  • BN depends on the batch; GroupNorm or InstanceNorm is often more stable when the batch is tiny.
  • Gradient accumulation does not enlarge the statistical range in one BN forward pass.
  • Freezing parameters does not automatically freeze BN running statistics.
  • A convolution immediately followed by BN normally uses bias=False.
