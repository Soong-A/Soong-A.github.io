上采样与转置卷积超详细入门：插值、尺寸公式、棋盘格与 U-Net 解码器

发表于2026-10-25|更新于2026-10-25|基础概念

阅读约 26 分钟 · 建议先看网格图，再读公式

图像分类最终只要输出一个类别，特征图可以一路从 $224 \times 224$ 缩到 $7 \times 7$。但语义分割要为每个像素判断类别，输出掩膜通常必须回到接近输入图像的分辨率。

这就需要上采样（upsampling）：把小特征图变成大特征图。

先记住本文最重要的边界：

上采样可以恢复尺寸，但不能凭空找回下采样时已经丢失的信息。它只能依据现有特征进行复制、插值或学习一种合理的填充方式。

在 U-Net 中，跳跃连接把编码器的高分辨率特征送到解码器，正是为了补充单靠上采样无法恢复的边界和位置细节。

阅读前：尺寸、数值和语义是三件不同的事

假设一张 $4 \times 4$ 图经过池化变成 $2 \times 2$：

图中的两张高分辨率图可以下采样成同一个低分辨率结果。只看这个低分辨率结果，无法唯一判断原来是哪一张。这叫信息不可逆。

所以评价一种上采样方法时要分开问：

  1. 它能不能得到所需的高和宽？
  2. 它怎样给新增位置赋值？
  3. 它有没有可学习参数？
  4. 它会不会引入规律性的伪影？

一、先认识四类常见方法

方法 怎样放大 有无参数 常见优点 常见风险
最近邻插值 复制最近的值 无 快、边界值不被平均 块状、锯齿
双线性插值 按距离加权平均 无 平滑、稳定 可能模糊细边界
转置卷积 用可学习核把输入散射到输出 有 放大方式可学习 重叠不均会产生棋盘格
插值 + 卷积 先固定放大，再学习修正 卷积有 职责清楚、通常稳健 有额外计算，仍可能过平滑

此外还有 MaxUnpooling、PixelShuffle、内容感知上采样等，后文会介绍它们适合什么场景。

二、最近邻插值：把一个格子复制成一片

假设输入是一个 $2 \times 2$ 网格：

最近邻放大 2 倍，会把每个值复制成 $2 \times 2$ 小块：

优点：

  • 计算非常快；
  • 不会创造输入中没有的新数值；
  • 对离散标签图，通常比线性插值合理。

缺点：

  • 放大图有明显方块感；
  • 斜线和曲线边缘容易呈阶梯状。

为什么标签掩膜常用最近邻

假设类别标签只有 0 和 1。如果用双线性插值，边界附近可能产生 $0.3$、$0.6$ 等值，它们不是合法类别编号。

如果掩膜是 one-hot 概率或软标签，要根据语义决定；这里说的是整数类别索引图。

三、双线性插值：先横向插，再纵向插

“双线性”可以拆成两次一维线性插值。

先看一维。已知两端：

若某个新位置距离左端占 25%，其值为：

$$10 \times 0.75 + 20 \times 0.25 = 12.5$$

二维位置周围有四个邻居，双线性插值会根据横向、纵向距离对四个值加权。离哪个角近，哪个角权重就大。

$$\frac{0 + 10 + 20 + 30}{4} = 15$$

真实框架需要根据输入和输出像素中心坐标确定权重，边界处也有明确规则，但“按距离对四邻域加权”是核心直觉。

align_corners 为什么总让人困惑

在 PyTorch 的双线性插值里：

  • align_corners=True：对齐输入与输出最角落像素的中心点；插值坐标会依赖输入和输出尺寸。
  • align_corners=False：按像素方格的边界对齐，超出部分使用边缘值；对相同 scale_factor 更具尺度一致性，也是多数现代图像任务的默认选择。

这不是“哪个绝对更准确”。如果要复现某篇论文、旧模型或标注处理流程，必须与其设置一致。模型训练和推理时也必须一致。

插值为什么没有可学习参数

权重只由几何距离决定，不通过数据训练。无论处理猫、CT 还是特征图，同样位置关系都会使用同样的插值规则。

这使它稳定、便宜，但也意味着它不知道“器官边界应该更锐利”或“这个纹理应该怎样恢复”。因此常在插值后再接卷积。

四、转置卷积不是卷积的逆运算

它的英文是 transposed convolution，也常被历史代码称为 deconvolution。这个旧称很容易让人误以为它能撤销卷积。

正确理解是：转置的是卷积对应的线性矩阵，不是求逆矩阵。

1. 把普通卷积想成矩阵乘法

把输入摊平成向量 $x$，一次线性卷积可写成：

$$y = C x$$

$C$ 是由卷积核和连接方式组成的稀疏矩阵。转置卷积使用同一连接关系的转置：

$$z = C^{\mathsf{T}} y$$

矩阵转置 $C^{\mathsf{T}}$ 一般不等于逆矩阵 $C^{-1}$。所以：

它能把张量映射回较大形状，但数值不会自动复原。

2. “滑动收集”与“散射相加”

理解普通卷积时，我们常想象卷积核在输入上滑动，每次收集一个局部窗口，计算一个输出值。

理解转置卷积时，可以反过来想：

  1. 取输入中的一个值；
  2. 让它乘以整个卷积核；
  3. 把所得小块撒到输出对应区域；
  4. 多个小块重叠的位置做加法。

这个“散射并相加”的视角，比“它是一种反卷积”更准确，也直接解释了棋盘格伪影为什么与重叠次数有关。

3. 等价的插零视角

对常见配置，转置卷积也可看成：

  1. 在相邻输入元素之间插入 $s - 1$ 个零；
  2. 按参数决定边界扩展或裁剪；
  3. 用步幅 1 做一次普通卷积式计算。

图中使用 kernel=2, stride=2, padding=0：$2 \times 2$ 输入经过等价过程得到 $4 \times 4$ 输出。插入的零只是帮助理解计算连接，不代表网络最终会在输出中留下零。

五、转置卷积输出尺寸公式

先写一维公式，高和宽分别计算。完整形式是：

$$H_{\text{out}} = (H_{\text{in}} - 1)\ s - 2p + d\ (k - 1) + p_{\text{out}} + 1$$

当 $d = 1$ 时，可化简为常见版本：

$$H_{\text{out}} = (H_{\text{in}} - 1)\ s - 2p + k + p_{\text{out}}$$

每个参数的直觉

参数 符号 代码参数 作用
输入尺寸 $H_{\text{in}}$ — 当前特征图高或宽
步幅 $s$ stride 相邻输入值在输出中的展开起点相隔多远
卷积核 $k$ kernel_size 每个输入值影响多大范围
padding $p$ padding 在转置尺寸关系中抵消两侧范围，数值越大输出越小
dilation $d$ dilation 拉开核元素间隔
output padding $p_{\text{out}}$ output_padding 在多种可行输出尺寸中选择其中一个

例 1：最常见的 2 倍放大

取 $H_{\text{in}} = 16$、$s = 2$、$k = 2$、$p = 0$、$p_{\text{out}} = 0$：

$$H_{\text{out}} = (16 - 1) \times 2 - 0 + 2 = 32$$

例 3：为什么需要 output_padding

普通 stride=2 卷积会跳过位置并使用向下取整，因此不同输入尺寸可能得到同一个输出尺寸。反过来只知道小特征图时，大尺寸不一定唯一。

例如：

取 $H_{\text{in}} = 5$、$s = 2$、$k = 3$、$p = 1$：

$$\begin{aligned}
p_{\text{out}} = 0 &\ \Longrightarrow\ H_{\text{out}} = 9 \cr
p_{\text{out}} = 1 &\ \Longrightarrow\ H_{\text{out}} = 10
\end{aligned}$$

$p_{\text{out}}$（代码里的 output_padding）用来选 9 还是 10。它主要调整输出形状，不是在已经算好的输出四周真的补一圈零，也不会因此新增可学习参数。

为什么转置卷积里的 padding 很反直觉

普通卷积公式里，给输入补边通常让输出更大；转置卷积公式里出现 $-2p$，参数越大输出反而越小。

一个实用策略是：不要只凭“padding”这个名字猜，直接把参数代入公式，并用一个随机张量在框架中打印 shape 验证。

六、棋盘格伪影是怎么产生的

转置卷积最著名的问题是输出出现周期性的明暗格或网格纹理，叫棋盘格伪影（checkerboard artifacts）。

1. 一维先看懂覆盖次数

假设 $k = 3$、$s = 2$。每个输入值影响连续 3 个输出位置，但下一个输入的展开起点向右移动 2 格：

中间区域会交替出现“被覆盖 2 次”和“被覆盖 1 次”的位置。即使输入和权重差不多，被加两次的位置也天然更容易数值偏大。

常见安全起点：

它们更容易形成均匀覆盖。危险例子：

但“可以整除”只是消除了结构上的一类不均匀，并不保证模型绝不会学出周期纹理。损失函数、初始化、边界处理和后续卷积都可能影响最终伪影。

3. 怎样判断伪影来自上采样

观察预测图或生成图：

  • 纹理是否以固定像素周期重复；
  • 横向和纵向是否形成规则格子；
  • 将转置卷积换成插值 + 卷积后，格子是否明显减弱；
  • 模型刚初始化、还未充分训练时是否已有周期图案。

规则而全局一致的网格更像结构伪影；只出现在真实边界附近的错误可能是特征不足、标签噪声或损失设计问题，不能都怪转置卷积。

最近邻 + 卷积还是双线性 + 卷积

  • 最近邻 + 卷积： 先复制，不主动平滑；卷积再学习怎样融合。生成模型和一些解码器常用。
  • 双线性 + 卷积： 起点更平滑；分割中常用，但极细边界可能被软化。

没有对所有数据都最优的固定答案。边界敏感任务可以同时比较 Dice、Hausdorff distance 和可视化，而不是只看平均损失。

与转置卷积公平比较参数量

不能只说哪一个“有参数”。两者通常都有可学习权重：

$$\begin{aligned}
\text{ConvTranspose} &: k \times k \times C_{\text{in}} \times C_{\text{out}} \cr
\text{Upsample} + \text{Conv} &: 3 \times 3 \times C_{\text{in}} \times C_{\text{out}}
\end{aligned}$$

插值本身无参数，但后面的卷积有。若转置卷积用 $k = 2$，它甚至可能比一个 $3 \times 3$ 卷积参数少。速度和显存也依赖具体形状、实现和硬件，需要实测。

九、奇数尺寸为什么经常差一个像素

假设输入高为 321，stride=2 下采样时会涉及向下取整或 padding：

再简单乘 2，可能得到 320 或 322，不一定回到 321。经过多级下采样后，每一级的舍入都会影响对应跳跃连接。

常用解决办法有三种：

方法 1：直接插值到 skip 的尺寸

这是最直接、可读性很高的办法。

方法 2：对称 padding

只适合 x 比 skip 小；如果差值可能为负，还要考虑裁剪。

方法 3：训练前把输入 pad 到网络步长的倍数

若编码器总下采样 5 次，总步长通常是 $2^5 = 32$。可以先把高宽 pad 到 32 的倍数，预测后再裁回原尺寸。滑窗推理和医学影像框架常采用这种思路。

十、另外三种上采样方式

1. MaxUnpooling：把最大值放回原位置

MaxPool 不只可以输出最大值，还可以记录最大值来自窗口中的哪个位置。MaxUnpooling 利用这些索引：

空位置仍是 0，需要后续卷积填充。SegNet 采用这种方法。它保存位置索引，但不能恢复被最大池化丢掉的其他数值。

2. PixelShuffle：把通道搬到空间

放大倍数为 $r$ 时，先用卷积生成 $C_{\text{out}} \cdot r^2$ 个通道，再重排：

$$(N,\ C_{\text{out}} r^2,\ H,\ W) \ \xrightarrow{\ \text{PixelShuffle}(r)\ } \ (N,\ C_{\text{out}},\ Hr,\ Wr)$$

它在超分辨率中很常见。它没有转置卷积的重叠覆盖机制，但不同子像素通道如果初始化或学习不一致，也可能出现周期纹理，所以不能简单等同于“绝对没有棋盘格”。

3. 内容感知上采样

CARAFE 等方法会根据局部内容预测重组权重，不再使用对所有位置都相同的固定插值规则。它可能更好地保留结构，但实现、计算和部署复杂度也更高，通常不是入门 U-Net 的第一选择。

十一、到底应该选哪一种

如果你正在写第一个 U-Net

先使用：

理由不是它在所有任务上都最准，而是行为清楚、尺寸容易控制、典型棋盘格风险较低，适合作为可靠基线。

如果论文或官方实现指定转置卷积

忠实复现，并检查：

  • kernel_size 是否能被 stride 整除；
  • padding 与 output_padding 是否给出目标尺寸；
  • 奇数输入时各级 shape 是否与 skip 对齐；
  • 输出可视化中是否出现周期网格。

经典 U-Net 和许多 nnU-Net 配置都可以合理地使用转置卷积。不能因为存在棋盘格风险，就断言所有转置卷积都不好。

如果处理离散标签掩膜

通常使用最近邻，避免制造不存在的类别编号。模型 logits 或连续概率图则可以按任务使用双线性插值。

如果做超分辨率

PixelShuffle、resize-convolution 和专门设计的重建模块都值得比较；评价重点不仅是像素误差，还包括纹理真实性和周期伪影。

十二、初学者最容易犯的十个错误

错误 1：认为上采样能找回原始细节

它只能扩大现有表示；丢失信息要依靠跳跃连接、上下文和学习到的先验补偿。

错误 2：把转置卷积叫作卷积的逆

它对应卷积线性算子的转置，不是逆运算。

错误 3：把 output_padding 当成真正补零

它用于消除输出形状歧义，主要选择输出尺寸，不是在输出图周围附加一圈实际零值。

错误 4：只看 scale factor，不打印 shape

奇数输入、多层 stride、padding 和 dilation 会共同影响尺寸。调试时直接打印每一级 x.shape 和 skip.shape。

错误 5：用双线性插值缩放整数类别 mask

这会制造无效类别值。整数标签一般使用最近邻。

错误 6：训练和推理使用不同的 align_corners

坐标映射变化会导致输出错位，尤其影响边界。

错误 7：认为 kernel 能被 stride 整除就绝无棋盘格

它只解决不均匀覆盖这一主要结构原因，模型仍可能学习到周期模式。

错误 8：上采样后直接与 skip 相加

标准 U-Net 通常按通道拼接；若要相加，两路通道数和语义都需专门设计。

错误 9：拼接后忘记通道数相加

$128$ 通道上采样特征与 $128$ 通道 skip 拼接后是 $256$ 通道，后续卷积的 in_channels 必须写 256。

错误 10：只比较参数量，不比较计算位置

在高分辨率特征图上做 3×3 卷积可能很贵。上采样前后何时降通道，会明显影响 FLOPs 和显存。

十三、用最小实验验证尺寸

遇到公式不确定时，不要靠猜：

手算高度和宽度：

$$\begin{aligned}
H_{\text{out}} &= (5 - 1) \times 2 - 2 \times 1 + 3 + 1 = 10 \cr
W_{\text{out}} &= (7 - 1) \times 2 - 2 \times 1 + 3 + 1 = 14
\end{aligned}$$

把公式、代码输出和网络目标尺寸三者对上，尺寸问题通常就解决了。

十四、四道自测题

1. 最近邻把 2×2 放大两倍时，每个输入值会变成多少个输出值？

在二维中会复制成 $2 \times 2$ 区域，因此每个输入值对应 4 个输出位置。

2. ConvTranspose2d 的 in=8、kernel=4、stride=2、padding=1、output_padding=0，输出多大？

$(8-1) \times 2 - 2 \times 1 + 4 = 16$，所以该维度正好放大两倍。

3. 为什么 kernel=3、stride=2 更容易出现棋盘格？

因为每个输入展开到 3 个位置，而起点每次移动 2 格，内部输出位置会交替被覆盖 1 次和 2 次；二维叠加后形成网格状不均匀。

4. U-Net 上采样后是 128×64×64，skip 也是 128×64×64，按通道拼接后 shape 是什么？

忽略 batch 维时是 $256 \times 64 \times 64$。空间尺寸不变，通道数相加。

最后用一张清单复习

  • 上采样恢复的是网格尺寸，不保证恢复丢失信息。
  • 最近邻复制值；双线性按四周距离加权；二者都没有学习参数。
  • 离散类别 mask 通常使用最近邻，不要插出小数类别。
  • 转置卷积是矩阵转置意义上的卷积，不是逆卷积。
  • 理解转置卷积可以用“每个输入把加权小块散射到输出，再把重叠相加”。
  • 完整输出公式要考虑 stride、padding、kernel、dilation 和 output_padding。
  • output_padding 用于选择输出形状，不是给最终结果真的补零。
  • 棋盘格的主要结构原因是重叠覆盖不均匀。
  • kernel 能被 stride 整除是更安全的起点，但不是无伪影保证。
  • U-Net 通常先上采样，再与 skip 按通道拼接，最后卷积融合。
  • 输入为奇数尺寸时，直接对齐到 skip.shape[-2:] 往往最容易排错。

About 26 minutes · Read the grid diagrams before the formulas

Image classification only needs to output one class, so its feature maps can shrink all the way from $224\times224$ to $7\times7$. Semantic segmentation must classify every pixel, so the output mask normally needs to return to almost the input image’s resolution.

This requires upsampling: turning a small feature map into a larger one.

First remember the most important boundary in this article:

Upsampling can restore spatial size, but it cannot magically recover information that was discarded during downsampling. It can only copy, interpolate or learn a plausible way to fill new positions from the remaining features.

In U-Net, skip connections deliver high-resolution encoder features to the decoder precisely because upsampling alone cannot reconstruct all boundary and positional detail.

Before reading: size, values and semantics are different things

Suppose pooling reduces a $4\times4$ image to $2\times2$:

The two high-resolution patterns in the diagram can produce the same low-resolution output. Looking only at that output, we cannot know which original was present. This is irreversible information loss.

When evaluating an upsampling method, ask four separate questions:

  1. Can it produce the required height and width?
  2. How does it assign values to new positions?
  3. Does it have learnable parameters?
  4. Can it introduce regular artifacts?

1. Four common families of methods

Method How it enlarges Parameters? Common advantage Common risk
Nearest-neighbour interpolation copies the nearest value no fast; does not average boundary labels blockiness and stair-step edges
Bilinear interpolation distance-weighted average no smooth and stable may blur fine boundaries
Transposed convolution uses a learned kernel to scatter inputs into the output yes learns how to enlarge uneven overlap can produce checkerboards
Interpolation + convolution fixed enlargement, then learned correction convolution only clear responsibilities and usually robust extra computation and possible oversmoothing

MaxUnpooling, PixelShuffle and content-aware upsampling are also useful. Later sections explain when to consider them.

2. Nearest-neighbour interpolation: copy one cell into a region

Suppose the input is a $2\times2$ grid:

Nearest-neighbour upsampling by a factor of two copies each value into a $2\times2$ block:

Advantages:

  • extremely fast;
  • creates no new numerical values that were absent from the input;
  • usually sensible for discrete label maps.

Disadvantages:

  • the enlarged image looks blocky;
  • diagonal and curved boundaries become staircase-shaped.

Why do label masks normally use nearest neighbour?

Suppose class labels can only be 0 or 1. Bilinear interpolation can produce 0.3 or 0.6 near a boundary, and those are not valid class indices.

One-hot probabilities and soft labels require a decision based on their semantics. The rule above applies to integer class-index maps.

3. Bilinear interpolation: interpolate horizontally, then vertically

“Bilinear” can be understood as two one-dimensional linear interpolations.

First consider one dimension:

If a new position is 25% of the way from the left endpoint, its value is:

$$10\times0.75+20\times0.25=12.5$$

A two-dimensional position has four neighbours. Bilinear interpolation weights them according to horizontal and vertical distance: the closer a corner, the larger its weight.

A centre-point example

Suppose the four input corners are:

The geometric centre is equally far from all four corners, so every weight is $1/4$:

$$\frac{0+10+20+30}{4}=15$$

Real frameworks determine weights from the centres of input and output pixels and define precise boundary behaviour. “Weight the four neighbours by distance” is the essential intuition.

Why is align_corners confusing?

In PyTorch bilinear interpolation:

  • align_corners=True aligns the centres of the corner pixels in the input and output; coordinates depend on both input and output size.
  • align_corners=False aligns the outer boundaries of the pixel squares and uses edge values outside the range. It is more scale-consistent for the same scale_factor and is the default choice in most modern vision tasks.

Neither setting is universally “more accurate”. To reproduce a paper, legacy model or annotation pipeline, use the same setting. Training and inference must also agree.

Why does interpolation have no learnable parameters?

Weights depend only on geometric distance and are not trained from data. The same spatial relationship uses the same rule whether the input is a cat, a CT scan or a feature map.

That makes interpolation stable and cheap, but it cannot know that an organ boundary should be sharper or a texture should be reconstructed in a particular way. A convolution is therefore often applied afterwards.

4. A transposed convolution is not the inverse of a convolution

The correct name is transposed convolution, although historical code often calls it “deconvolution”. That old name easily suggests that it can undo a convolution.

The accurate statement is: the matrix representing the convolution is transposed; it is not inverted.

4.1 View an ordinary convolution as matrix multiplication

Flatten the input into a vector $x$. A linear convolution can be written as:

$$y=Cx$$

$C$ is a sparse matrix determined by the kernel and connectivity. A transposed convolution uses the transpose of that connectivity:

$$z=C^{\mathsf T}y$$

In general, $C^{\mathsf T}$ is not the inverse $C^{-1}$. Therefore:

It can map a tensor back to a larger shape, but its values are not automatically reconstructed.

4.2 “Gather while sliding” versus “scatter and add”

We often picture an ordinary convolution sliding a kernel over the input, gathering a local window and producing one output value.

For a transposed convolution, reverse the perspective:

  1. take one input value;
  2. multiply it by the complete kernel;
  3. scatter the resulting patch into the corresponding output region;
  4. add patches wherever they overlap.

This scatter-add view is more accurate than “inverse convolution” and directly explains why checkerboards depend on overlap counts.

4.3 An equivalent zero-insertion view

For common settings, a transposed convolution can also be viewed as:

  1. insert $s-1$ zeros between adjacent input values;
  2. expand or crop the boundary according to the parameters;
  3. perform an ordinary stride-1 convolution-style computation.

The diagram uses kernel=2, stride=2, padding=0: a $2\times2$ input becomes a $4\times4$ output. Inserted zeros are only a way to understand connectivity; they do not mean the trained network must leave zeros in the final output.

5. Output-size formula for transposed convolution

Write the one-dimensional formula first and apply it separately to height and width:

$$H_{\text{out}}=(H_{\text{in}}-1)s-2p+d(k-1)+p_{\text{out}}+1$$

When $d=1$, it simplifies to the familiar form:

$$H_{\text{out}}=(H_{\text{in}}-1)s-2p+k+p_{\text{out}}$$

Intuition for every parameter

Parameter Symbol Code argument Role
Input size $H_{\text{in}}$ — current feature-map height or width
Stride $s$ stride distance between the output starting points of adjacent input values
Kernel $k$ kernel_size region influenced by one input value
Padding $p$ padding cancels extent on both sides; larger values reduce the transposed-convolution output
Dilation $d$ dilation spreads kernel elements apart
Output padding $p_{\text{out}}$ output_padding selects one of several possible output sizes

Example 1: the most common 2× enlargement

Take $H_{\text{in}}=16$, $s=2$, $k=2$, $p=0$ and $p_{\text{out}}=0$:

$$H_{\text{out}}=(16-1)\times2-0+2=32$$

Example 2: kernel=4 can also enlarge by two

Take $H_{\text{in}}=16$, $s=2$, $k=4$ and $p=1$:

$$H_{\text{out}}=(16-1)\times2-2+4=32$$

Example 3: why is output_padding needed?

An ordinary stride-2 convolution skips positions and rounds down, so different input sizes can produce the same output size. In the reverse direction, knowing only the small feature map does not uniquely determine the larger size.

For $H_{\text{in}}=5$, $s=2$, $k=3$ and $p=1$:

$$\begin{aligned}
p_{\text{out}}=0 &\ \Longrightarrow\ H_{\text{out}}=9 \cr
p_{\text{out}}=1 &\ \Longrightarrow\ H_{\text{out}}=10
\end{aligned}$$

output_padding selects 9 or 10. It mainly resolves the output shape. It does not literally append a ring of zeros around an already computed output, and it adds no learnable parameters.

Why does transposed-convolution padding feel backwards?

In the ordinary-convolution formula, padding the input normally makes the output larger. The transposed-convolution formula contains $-2p$, so increasing padding makes its output smaller.

A practical rule is not to guess from the word “padding”. Substitute the values into the formula and verify the result by printing the shape of a random tensor in the framework.

6. Where do checkerboard artifacts come from?

The best-known transposed-convolution problem is a periodic bright-and-dark grid called a checkerboard artifact.

6.1 Understand overlap counts in one dimension

6.3 How can you tell whether an artifact comes from upsampling?

Inspect the prediction or generated image:

  • does the texture repeat at a fixed pixel period?
  • do horizontal and vertical lines form a regular grid?
  • does replacing transposed convolution with interpolation plus convolution greatly reduce the pattern?
  • is a periodic pattern visible immediately after initialisation, before substantial training?

A regular global grid suggests a structural artifact. Errors restricted to real object boundaries may instead come from weak features, label noise or the loss function; do not blame every boundary error on transposed convolution.

7. Interpolation + convolution: separate enlargement from learning

A common block is:

Responsibilities are explicit:

This avoids the classic checkerboard mechanism caused by unevenly overlapping scatter regions. Any learned network can still produce other texture artifacts, so this is not a mathematical guarantee of artifact-free output.

Nearest + convolution or bilinear + convolution?

  • Nearest + convolution: copy first without deliberate smoothing; let the convolution learn how to mix. Common in generative models and some decoders.
  • Bilinear + convolution: starts from a smoother feature map and is common in segmentation, but may soften very thin boundaries.

No fixed choice wins on every dataset. For boundary-sensitive tasks, compare Dice, Hausdorff distance and visualisations rather than only the average loss.

Compare parameters fairly with transposed convolution

It is not enough to ask which method “has parameters”. Both usually contain learned weights:

$$\begin{aligned}
\text{ConvTranspose}&: k\times k\times C_{\text{in}}\times C_{\text{out}} \cr
\text{Upsample} + \text{Conv}&: 3\times3\times C_{\text{in}}\times C_{\text{out}}
\end{aligned}$$

Interpolation itself has no parameters, but the following convolution does. A transposed convolution with $k=2$ can even have fewer parameters than a 3×3 convolution. Speed and memory also depend on the exact shapes, implementation and hardware, so benchmark them.

9. Why are odd input sizes often off by one pixel?

Suppose the input height is 321. A stride-2 downsampling operation rounds according to its padding and formula:

Simply multiplying by two later gives 320 or 322, not necessarily 321. After several downsampling stages, rounding at each stage affects the corresponding skip connection.

Method 1: interpolate directly to the skip size

Method 2: symmetric padding

This only handles the case where x is smaller than skip. If a difference can be negative, cropping must also be considered.

Method 3: pad inputs to a multiple of the network stride

If an encoder downsamples five times, its total stride is normally $2^5=32$. Pad height and width to multiples of 32 before the network, then crop the prediction back to the original size. Sliding-window inference and medical-imaging frameworks often follow this approach.

10. Three other upsampling methods

10.1 MaxUnpooling: put maxima back at their original positions

MaxPool can output not only each maximum value but also the index from which it came. MaxUnpooling uses those indices:

Empty positions remain zero and need later convolutions to fill them. SegNet uses this method. It preserves positional indices but cannot recover the other values discarded by max pooling.

10.2 PixelShuffle: move channels into space

For enlargement factor $r$, a convolution first produces $C_{\text{out}}r^2$ channels and then rearranges them:

$$(N,\ C_{\text{out}}r^2,\ H,\ W)\ \xrightarrow{\ \text{PixelShuffle}(r)\ }\ (N,\ C_{\text{out}},\ Hr,\ Wr)$$

It is common in super-resolution. PixelShuffle lacks the overlapping-patch mechanism of transposed convolution, but inconsistent initialisation or learning between sub-pixel channels can still create periodic texture. It is not automatically “checkerboard-proof”.

10.3 Content-aware upsampling

Methods such as CARAFE predict reassembly weights from local content instead of applying the same fixed interpolation rule everywhere. They may preserve structure better, but increase implementation, compute and deployment complexity and are not usually the first choice for a beginner U-Net.

If you are implementing your first U-Net

Start with:

Not because it is always the most accurate, but because its behaviour is clear, its sizes are easy to control and its risk of classic checkerboards is low. It is a reliable baseline.

If a paper or official implementation specifies transposed convolution

Reproduce it faithfully and check:

  • whether kernel_size is divisible by stride;
  • whether padding and output_padding produce the target size;
  • whether odd-sized inputs align at every skip connection;
  • whether output visualisations contain a periodic grid.

Classic U-Net and many nnU-Net configurations use transposed convolution successfully. The existence of checkerboard risk does not make every transposed convolution bad.

If you are resizing a discrete label mask

Normally use nearest neighbour so that no invalid class indices are invented. Model logits and continuous probability maps may use bilinear interpolation when appropriate.

If you are working on super-resolution

Compare PixelShuffle, resize-convolution and specialised reconstruction modules. Evaluate not only pixel error but also texture realism and periodic artifacts.

Need Suggested starting point

12. Ten mistakes beginners often make

Mistake 1: assuming upsampling recovers the original detail

It only enlarges the remaining representation. Lost information must be compensated by skip connections, contextual features and learned priors.

Mistake 2: calling transposed convolution the inverse of convolution

It corresponds to the transpose of convolution’s linear operator, not its inverse.

Mistake 3: treating output_padding as literal zero-padding

It resolves an output-shape ambiguity. It does not append actual zeros around the final output.

Mistake 4: checking only the scale factor instead of printing shapes

Odd inputs, several strides, padding and dilation all affect the size. Print x.shape and skip.shape at every level while debugging.

Mistake 5: resizing an integer class mask with bilinear interpolation

This creates invalid class values. Integer labels normally use nearest neighbour.

Mistake 6: changing align_corners between training and inference

The coordinate mapping changes and can shift the output, especially near boundaries.

Mistake 7: believing divisibility guarantees no checkerboards

It removes the main structural source of uneven coverage, but the model can still learn periodic patterns.

Mistake 8: adding the upsampled feature directly to the skip

Standard U-Net concatenates along the channel dimension. Addition requires deliberately matched channel counts and compatible semantics.

Mistake 9: forgetting that concatenation adds channel counts

Concatenating a 128-channel upsampled feature with a 128-channel skip produces 256 channels. The next convolution must use in_channels=256.

Mistake 10: comparing parameter counts but ignoring where computation happens

A 3×3 convolution on a high-resolution feature map can be expensive. Whether channels are reduced before or after upsampling can substantially change FLOPs and memory use.

13. Verify sizes with a minimal experiment

When uncertain about the formula, do not guess:

Calculate height and width by hand:

$$\begin{aligned}
H_{\text{out}}&=(5-1)\times2-2\times1+3+1=10 \cr
W_{\text{out}}&=(7-1)\times2-2\times1+3+1=14
\end{aligned}$$

Once the formula, code output and intended network size agree, most shape problems are solved.

14. Four self-check questions

1. When nearest neighbour enlarges a 2×2 grid by a factor of two

In two dimensions it becomes a $2\times2$ region, so every input value corresponds to four output positions.

2. ConvTranspose2d has input size 8

$(8-1)\times2-2\times1+4=16$, so that dimension is exactly doubled.

3. Why is kernel=3

Each input spreads to three positions while starting points move by two. Interior output positions alternate between one and two overlaps; in two dimensions the unevenness forms a grid.

4. A U-Net upsampled feature is 128×64×64 and the skip is also 128×64×64. What is the shape after channel concatenation?

Ignoring the batch dimension, it is $256\times64\times64$. Spatial size is unchanged and channel counts are added.

Final review checklist

  • Upsampling restores grid size but does not guarantee recovery of lost information.
  • Nearest neighbour copies values; bilinear interpolation weights four neighbours by distance; neither has learned parameters.
  • Discrete class masks normally use nearest neighbour so interpolation does not invent fractional classes.
  • Transposed convolution is a convolution in the matrix-transpose sense, not an inverse convolution.
  • Understand it as each input scattering a weighted patch into the output and overlapping patches being added.
  • The complete output formula includes stride, padding, kernel, dilation and output padding.
  • output_padding selects the output shape; it does not literally pad the final result with zeros.
  • Uneven overlap is the main structural source of checkerboard artifacts.
  • A kernel divisible by the stride is a safer starting point, not an artifact-free guarantee.
  • U-Net normally upsamples, concatenates with the skip along channels, and then fuses with convolution.
  • For odd input sizes, directly matching skip.shape[-2:] is often the easiest solution to debug.
