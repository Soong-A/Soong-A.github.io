CS231n foundations — teaching a machine to see

发表于2025-08-02|更新于2026-10-11|English Notes
|浏览量:

Studied summer 2025 · notes tidied up later · 36 min read

中文版：CS231n 基础篇：如何教机器看见

Stanford’s CS231n in the summer of 2025, followed through 子豪兄’s Chinese walkthrough on Bilibili. I was not trying to transcribe lectures. I wanted to rebuild each idea in my own words and leave myself diagrams I could come back to — which turned out to matter three months later when I started reading segmentation papers.

The journey the course keeps repeating

flowchart TD
  A[Raw pixels as a grid of numbers] --> B[Score function]
  B --> C[One score per class]
  C --> D[Loss function measures wrongness]
  D --> E[Gradient of loss w.r.t. every weight]
  E --> F[Optimiser updates weights]
  F --> B

Everything else — convolution, batch norm, residual connections — refines one stage of that loop. Knowing which stage a new idea touches is most of understanding it.

The loop has one property that is easy to miss: it closes. Once the optimiser has changed the weights, the next batch walks the same path again. Any change anywhere gets repeated thousands of times — which is why a decision that looks tiny (the scale of the initialisation, the order of magnitude of the learning rate, whether you subtracted the mean) is enough to decide whether training converges or diverges.

I eventually found that the fastest way to read a new paper is to ask which stage it touches. ResNet changes how gradients get back to the early layers. Batch norm changes the input distribution each layer sees. Adam changes how the optimiser takes its step. They are not editing the same stage, which is exactly why they stack — and why a modern network reads like a collection of patches.

One more thing worth saying early: the only stage we genuinely design is the score function. The rest is close to boilerplate. Two thirds of the course is really one question asked repeatedly — what should the score function look like?

Part I — From pixels to scores

1. Why not nearest neighbour

The course opens with k-NN precisely so it can be discarded. It has zero training cost and enormous test cost, which is exactly backwards for deployment. Worse, pixel-wise L2 distance is almost meaningless for images: shift a picture three pixels right and the distance explodes while the content is identical.

Approach Train cost Test cost Learns features?
k-Nearest Neighbour None O(N) per query No
Linear classifier Moderate O(1) per query Weights only
Convolutional network High O(1) per query Yes, hierarchically

It also introduces the idea that outlives it: a hyperparameter is chosen on validation data, never on test data.

2. The linear classifier, and what W actually is

Flatten the image to a vector x, compute s = Wx + b. Each row of W is a template for one class, and the score is a dot product — a similarity measurement.

Visualising the learned rows of W on CIFAR-10 is the moment the course lands: the “horse” template has two heads, because it is averaging left-facing and right-facing horses into one image. A linear model gets exactly one template per class, and that is its ceiling.

3. Two losses, two philosophies

flowchart TD
  A[Class scores s] --> B[Multiclass SVM hinge loss]
  A --> C[Softmax cross-entropy]
  B --> D[Wants correct score above others by a margin]
  C --> E[Turns scores into probabilities then maximises log likelihood]
  D --> F[Zero loss once the margin is met]
  E --> G[Always a little more to gain]
SVM (hinge) Softmax (cross-entropy)
Output Uncalibrated scores A probability distribution
Once correct by a margin Loss is exactly 0, stops pushing Keeps nudging toward certainty
Interpretation Geometric margin Maximum likelihood

A useful sanity check the course drills: at initialisation, with all scores near zero, softmax loss should be about log(C) — for CIFAR-10 that is log(10) ≈ 2.3. If your first printed loss is not roughly that, the bug is before training even starts.

4. Regularisation expresses a preference

Regularisation is not only about overfitting. Given two weight vectors that produce identical scores, it decides which one you prefer.

L2 spreads weight across many features rather than betting everything on one — which generalises better because it depends on more of the evidence. L1 does the opposite: it drives weights to exactly zero, producing sparse models.

5. Optimisers: SGD and its descendants

Plain gradient descent has two failure modes the course makes vivid: it crawls along shallow directions while oscillating across steep ones, and it stops dead at any saddle point where the gradient is zero.

Optimiser Idea Fixes
SGD Step along the gradient —
SGD + Momentum Accumulate a velocity Oscillation, saddle points
AdaGrad Divide by accumulated squared gradients Different scales per parameter
RMSProp AdaGrad with a decaying average AdaGrad’s learning rate dying to zero
Adam Momentum and RMSProp together, with bias correction Both, and it is the sane default

Defaults that work almost everywhere: beta1 = 0.9, beta2 = 0.999, lr = 1e-3. Learning-rate decay — cosine or step — is applied after you have a run that trains at all, not before.

Part II — Making it actually learn

6. Backpropagation is bookkeeping, not magic

flowchart TD
  A[Forward pass computes and caches values] --> B[Loss at the end]
  B --> C[Local gradient at each node]
  C --> D[Chain rule multiplies along the path]
  D --> E[Gradient for every parameter]
  E --> F[One optimiser step]

The idea that made it click: each gate only needs to know its local derivative. It receives an upstream gradient, multiplies by its own, and passes the result down. No node needs a view of the whole network.

When a value is used in two places, its gradients add. That one rule is what makes residual connections work.

7. Activations, and the dying ReLU

Activation Problem it has
Sigmoid Saturates at both ends, gradients vanish; output not zero-centred
Tanh Zero-centred, but still saturates
ReLU Converges far faster; but a unit can die
Leaky ReLU Small slope when negative, so it never fully dies

Sigmoid saturation kills learning because the local derivative approaches zero far from the origin, and the chain rule multiplies it into everything upstream.

The dying ReLU is worth naming: if a unit’s input is negative for every training example, its gradient is always zero, and it never updates again. It is permanently dead. A learning rate that is too large is the usual cause — one huge update pushes the weights somewhere they can never come back from.

8. Weight initialisation

Set every weight to zero and every neuron in a layer computes the same thing forever — they receive identical gradients and stay identical. Symmetry has to be broken by randomness.

But the scale of that randomness decides whether the network trains at all:

He initialisation has the factor of 2 precisely because ReLU discards the negative half of the distribution, halving the variance — so you put it back.

9. Batch normalisation

Normalise each layer’s inputs to zero mean and unit variance across the mini-batch, then let the network learn a scale γ and shift β to undo it if it wants to.

flowchart TD
  A[Layer input across the batch] --> B[Subtract the batch mean]
  B --> C[Divide by the batch standard deviation]
  C --> D[Learned affine transform with gamma and beta]
  D --> E[Output to the next layer]

What it buys you: larger learning rates, far less sensitivity to initialisation, and a mild regularising effect. What it costs you: the behaviour now differs between training and test time, because at test time there is no batch to normalise over — running averages collected during training are used instead. Forgetting to switch to eval mode is one of the most common bugs in the whole field.

10. Regularisation in practice

Technique What it does Still standard?
L2 weight decay Penalises large weights Yes, always
Dropout Randomly zeroes activations during training Less so in conv nets since batch norm
Data augmentation Flips, crops, colour jitter, scale Yes, and it is free
Early stopping Stop when validation error turns upward Yes

They share one pattern: add randomness during training, average it out at test time. Dropout zeroes units while training and scales activations at test; augmentation perturbs inputs while training and uses the clean image at test; batch norm uses batch statistics while training and running averages at test.

Part III — Convolutional networks

11. Convolution: one reusable question

A fully connected layer on a 224×224×3 image needs ~150k weights per neuron. A convolution asks the same small question at every position instead.

flowchart TD
  A[Input volume] --> B[Filter slides over every position]
  B --> C[Dot product at each location]
  C --> D[One activation map per filter]
  D --> E[Stack maps into an output volume]
  E --> F[Non-linearity then pooling]

Two properties do the work:

  • Weight sharing — the same filter is reused everywhere, so an edge detector learned in the corner also works in the centre.
  • Local connectivity — each output depends on a small patch, so spatial structure survives instead of being flattened away.

12. Pooling and the receptive field

Pooling downsamples each activation map independently — it never mixes channels, and it has no parameters.

Receptive field is the part I had to draw to believe. Stacking three 3×3 layers sees the same 7×7 region as one 7×7 layer:

Depth Effective receptive field Parameters (C channels)
One 7×7 layer 7×7 49C²
Three 3×3 layers 7×7 27C²

Fewer parameters, two extra non-linearities, same view. That single observation explains most of VGG — and explains why almost nobody uses large kernels in the middle of a network any more.

13. Architectures as a sequence of fixes

Year Network The problem it solved
2012 AlexNet Proved deep CNNs beat hand-designed features
2014 VGG Showed small stacked 3×3 filters beat large ones
2014 GoogLeNet Cut parameters with 1×1 bottlenecks and parallel branches
2015 ResNet Residual connections made 100+ layers trainable

The 1×1 convolution deserves its own note. It looks pointless — a kernel that sees one pixel — but it operates across all channels at that pixel, so it is a cheap way to mix and reduce channel depth before an expensive 3×3. That is the whole trick behind GoogLeNet’s inception block and ResNet’s bottleneck.

14. ResNet, in a little more detail

The motivating observation is counter-intuitive: a 56-layer plain network performed worse than a 20-layer one on training data. Not overfitting — an optimisation failure. The deeper network could not even learn to copy the shallower one.

flowchart TD
  A[Input x] --> B[Weight layer]
  B --> C[ReLU]
  C --> D[Weight layer]
  D --> E[Add x back]
  A --> E
  E --> F[ReLU then next block]

So let the block learn a residual F(x) and compute F(x) + x. If the extra depth cannot help, driving F(x) to zero recovers the identity — which is far easier than learning the identity from scratch. And because addition passes gradients through unchanged, the backward path reaches early layers directly.

15. Transfer learning, which is what you will actually do

flowchart TD
  A[Check dataset size and domain similarity] --> B[Small and similar]
  A --> C[Small and different]
  A --> D[Large enough to fine-tune broadly]
  B --> E[Freeze most of the backbone and train a new head]
  C --> F[Keep early generic layers and tune later layers carefully]
  D --> G[Fine-tune most or all layers with a low learning rate]

Training from scratch is the rare case, not the default. Early layers learn edges and colour blobs that transfer almost everywhere — which is exactly why MM-UNet initialises its 3D encoder from 2D ImageNet weights.

When fine-tuning, use a learning rate roughly 10× smaller than you would for training from scratch. The pretrained weights are already good; large steps destroy them.

16. The training checklist

Most of my early failures were not architecture problems.

flowchart TD
  A[Preprocess: subtract the mean] --> B[Initialise with He or Xavier]
  B --> C[Check the initial loss is about log of C]
  C --> D[Overfit twenty examples to 100 percent]
  D --> E[If that fails the bug is in the code not the model]
  D --> F[Then add regularisation and full data]
  F --> G[Search learning rate on a log scale]
  G --> H[Watch training and validation curves together]
  • Search the learning rate over 1e-1 … 1e-5, logarithmically, not linearly.
  • Do a coarse random search first, then a fine one around what worked. Random beats grid search, because most hyperparameters do not matter equally.
  • A loss curve that is flat then suddenly drops usually means bad initialisation.
  • A gap between train and validation that keeps widening means it is time for more regularisation, not more epochs.

17. Beyond classification

Once the backbone works, the same features serve other tasks by changing only the head:

Task Output Typical approach
Classification One label Backbone plus a dense layer
Semantic segmentation A label per pixel Encoder–decoder, e.g. U-Net
Object detection Boxes plus labels Region proposals or single-shot regression
Instance segmentation A mask per object Detection plus a mask head

Semantic segmentation is where my own work went. The key structural problem is that downsampling destroys the spatial precision you need to place a boundary — which is exactly what skip connections in U-Net, and AFFM in MM-UNet, exist to repair.

18. What did the network actually learn?

The course spends real time on interpretability, and it changed how I read results.

  • First-layer filters are directly viewable, and they always come out as edges, colours and blobs — in every network, on every dataset. That universality is why transfer learning works.
  • Occlusion maps: slide a grey square over the image and record how the correct-class probability drops. Where it drops most is what the model was relying on.
  • Saliency: the gradient of the class score with respect to the input pixels — which pixels, if changed slightly, would change the answer most.

The uncomfortable finding: models sometimes score well by relying on the wrong thing entirely — background, watermarks, an artefact of how the data was collected. In medical imaging that failure mode is not academic, which is why I kept coming back to this section.

What stayed with me

CS231n gave me the vocabulary to read a segmentation paper and immediately ask the right questions: what is the score function, what is the loss, where does the gradient flow, what is the receptive field at this depth, and what is the model actually keying on. Without that, papers are a list of module names.
