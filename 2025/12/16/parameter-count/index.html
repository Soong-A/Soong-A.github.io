参数量：逐层数清一个模型

发表于2025-12-16|更新于2026-10-11|基础概念
|浏览量:

阅读约 3 分钟

在深度学习和模型轻量化领域，“参数个数”是一个衡量模型大小、复杂度和内存占用的关键指标。

简单来说，参数个数就是模型中所有需要通过学习（训练）来确定的数值的总数。这些数值决定了模型如何对输入数据进行转换和预测。

下面从几个层面详细解释：

一、参数是什么？

模型参数主要包括：

  1. 权重：连接神经元之间的强度值。
  2. 偏置：为神经元提供基础的激活阈值。

训练过程就是通过大量数据，不断调整这些权重和偏置，使得模型的输出尽可能接近正确答案。

二、参数是如何计算出来的？（按层解析）

参数的数量不涉及输入数据，只由**模型自身的结构（架构）**决定。我们通过计算每一层的参数，然后求和得到总量。

1. 全连接层

这是最直观的。如果一层有 m 个输入神经元和 n 个输出神经元，那么：

  • 权重数 = m * n （每个输入和每个输出之间都有一个连接权重）
  • 偏置数 = n （每个输出神经元有一个偏置）
  • 该层总参数 = (m * n) + n

举例：一个输入为1000维，输出为500维的全连接层，其参数为 (1000 * 500) + 500 = 500,500。可以看到，全连接层的参数增长非常快，是导致模型臃肿的主因之一。

2. 卷积层

卷积层的参数与输入图像大小无关，只与卷积核的大小、数量和深度有关。对于一个卷积层，假设：

  • 输入通道数为 C_in
  • 输出通道数（即卷积核数量）为 C_out
  • 卷积核尺寸为 K * K（例如3x3）

那么：

  • 每个卷积核的参数：一个卷积核要处理输入的所有通道，所以单个卷积核的权重数为 C_in * K * K，加上1个偏置。
  • 该层总参数：因为有 C_out 个卷积核，所以总参数 = C_out * (C_in * K * K + 1)

举例：一个卷积层，输入通道为3（RGB图像），输出通道为64，使用3x3卷积核。参数 = 64 * (3 * 3 * 3 + 1) = 64 * 28 = 1,792 这正是卷积神经网络相对轻量的原因：参数共享。一个3x3的卷积核可以滑动检测整张图片的特征，而不需要像全连接层那样为每个像素位置都设置独立的权重。

3. 归一化层、池化层

  • 批量归一化层：有可学习的缩放参数 γ 和偏移参数 β，每个通道一对。如果通道数为 C，则参数为 2 * C。这个数量通常很少。
  • 池化层：没有可学习的参数。它只是执行一个固定的计算规则（如取最大值、求平均值）。

三、如何与您提供的文本和图1联系起来？

在您提到的轻量级皮肤病变分割的上下文中：

  1. UNeXt 为何能“减少参数”？
    • 传统的U-Net使用大量卷积层。UNeXt用 “tokenized MLP块” 替代了部分卷积操作。
    • MLP（多层感知机）本质上是全连接层，但UNeXt的关键在于“tokenization”和局部MLP。它将特征图分割成局部小块（token），在每个小块内部或小块之间进行轻量级的MLP计算。
    • 这样做避免了传统卷积堆叠带来的通道数爆炸性增长，也避免了全局全连接层的巨大参数量，从而在整体上实现了参数量的显著降低。
  2. 为什么图1用“参数个数”作为X轴？
    • 参数量直接决定模型大小：参数量越少，模型文件越小（例如从几百MB降到几MB），越容易部署到手机、边缘设备。
    • 间接影响速度和能耗：参数少的模型，推理时需要移动的内存数据也少，通常计算量（GFLOPs）也更低，因此更快、更省电。
    • 展示“权衡”关系：图1的目的就是展示，在追求轻量化（X轴向左）的同时，如何尽可能保持高精度（Y轴向上）。这是一个核心的工程与科研权衡。

四、在实际中如何获知参数量？

研究人员和工程师不需要手动计算每一层。常用的深度学习框架都提供了简单的函数来统计总参数量：

  • PyTorch: sum(p.numel() for p in model.parameters())
  • TensorFlow/Keras: model.count_params()

In deep learning and model compression, parameter count is the standard measure of a model’s size, complexity and memory footprint.

Put simply: it is the total number of values the model has to learn. Those values determine how the model transforms its input into a prediction.

What counts as a parameter

  1. Weights — the connection strengths between units.
  2. Biases — the baseline activation offset for each unit.

Training is the process of adjusting those two things, over many examples, until the output is close enough to the right answer.

Counting them, layer by layer

Parameter count does not depend on the input data at all. It is determined entirely by the model’s own architecture.

Fully connected layer

With m input units and n output units:

  • Weights = m × n — every input connects to every output.
  • Biases = n — one per output unit.
  • Total = (m × n) + n

Dense layers grow fast. They are one of the main reasons models become bloated.

Convolutional layer

Crucially, this does not depend on the input image size — only on the kernel.

  • Input channels: C_in
  • Output channels (number of filters): C_out
  • Kernel: K × K

Each filter must span all input channels, so one filter holds C_in × K × K weights plus one bias:

For 3 input channels (RGB), 64 output channels, 3×3 kernel:

This is exactly why convolutional networks are comparatively light: weight sharing. One 3×3 kernel slides across the whole image to detect a feature, instead of a dense layer needing separate weights for every pixel position.

Normalisation and pooling

Layer Parameters
Batch normalisation 2 × C — a scale γ and a shift β per channel
Pooling None — it applies a fixed rule such as max or average

Batch norm’s contribution is real but usually small.

Why papers plot parameters on the x-axis

In the lightweight segmentation literature — UNeXt and similar — figures typically put parameter count on the x-axis and accuracy on the y-axis. Two reasons:

  1. Parameters determine model size directly. Fewer parameters means a smaller file, which is what makes deployment to a phone or an edge device possible at all — the difference between hundreds of megabytes and a few.
  2. They correlate with speed and energy. Fewer parameters usually means less data movement during inference, which usually means lower GFLOPs, faster execution and less power.

The figure exists to show the trade-off: how far left can you move without falling down the y-axis.

How UNeXt reduces parameters

It replaces some convolutional stages with tokenised MLP blocks. The key is the tokenisation plus locality: the feature map is split into local patches, and lightweight MLP computation happens within or between those patches. That avoids both the channel explosion of stacked convolutions and the enormous cost of a global dense layer.

The part worth internalising

Parameter count and GFLOPs answer different questions. Parameters tell you how big the model is; GFLOPs tell you how much work one prediction costs. A model can be small and slow, or large and fast. Reporting only one of them hides half the picture.
