吴恩达机器学习专项课程：一张完整的基础地图

发表于2025-07-06|更新于2026-10-11|学习笔记
|浏览量:

2025 年暑假学习 · 后来整理成文 · 阅读约 34 分钟

English version: Andrew Ng’s Machine Learning Specialization — the foundation map

2025 年暑假，在动手写任何研究代码之前，我先跟着 最新吴恩达机器学习 DeepLearning.ai 课程（双字） 把这门专项课完整过了一遍。这是我会推荐给一年前的自己的课：它不允许你把模型当成黑箱，而且始终在重复同样的三个问题。

下面这些是我真的会回头翻的笔记。

整门课的形状

专项课里几乎所有内容都套在同一个模板上：选一个模型，选一种衡量”错得多离谱”的方式，再选一种把它变小的方式。

flowchart TD
  A[模型 f w b] --> B[代价函数 J]
  B --> C[优化器]
  C --> D[更新后的参数]
  D --> A
  B --> E[诊断：偏差还是方差]
  E --> F[调整数据、特征或正则化]
  F --> A

对任意一个算法，如果我能说清这三样东西，就说明我理解到了能调试它的程度；说不清，那我只是记住了它的名字。

课程 核心问题 新增了什么
1 · 监督学习 怎样拟合并评估一个模型？ 线性回归、逻辑回归、梯度下降、正则化
2 · 高级算法 怎样做出更强的模型，并且知道它到底行不行？ 神经网络、Adam、模型评估、决策树、集成方法
3 · 无监督与强化学习 没有标签、甚至没有数据集怎么办？ 聚类、异常检测、推荐系统、PCA、强化学习

第一部分 —— 监督学习

一、线性回归就是整套方法的缩影

模型是加权求和，代价是均方误差，优化器是梯度下降。

有两个细节很容易跳过，而跳过的代价不小：

  • 特征缩放。 如果一个特征的范围是 0–2000，另一个是 0–5，代价曲面会变成一条狭长的山谷，梯度下降只能来回折线前进。归一化不是为了好看，它直接决定你需要多少步。
  • 学习率是可以被诊断的。 代价上升说明 α 太大；代价下降但几乎不动说明 α 太小。把 J 对迭代次数画出来，是整门课里最便宜的调试工具。

优化器永远不知道答案好不好，它只知道往哪个方向走代价会变小。模型是否正确，全都藏在你怎样定义代价函数和数据里。

代价里的 1/2 是干嘛的

纯粹是为了和平方求导出来的那个 2 抵消。它不改变最小值的位置，只让梯度写出来干净一点。

二、向量化，以及循环为什么消失了

写成显式循环和写成 np.dot，算出来的数字完全一样，但跑起来不一样快。

NumPy 把计算交给底层优化过的例程，用上 CPU 的并行指令。模型很小的时候差别看不出来；规模一上来，就是几分钟和几小时的区别。这也是为什么梯度下降被写成矩阵更新而不是嵌套循环——数学完全相同，执行方式不同。

三、特征工程与多项式拟合

线性模型只是对参数线性，对原始输入并不是。把一个特征平方、把两个特征相乘、取个对数——一条直线模型就能拟合曲线。

第三行才是真正有用的一课：临街宽 × 进深 就是面积，而面积才是真正决定房价的东西。特征工程是领域知识唯一能进入模型的入口。

多项式特征让缩放变成必须的：如果 面积 能到 1000，面积³ 就是十亿量级，梯度下降会爬得极慢。

四、逻辑回归：同一套机器，不同的输出

把同样的 wx + b 套进 sigmoid，它就变成了概率；再把平方误差换成交叉熵，代价曲面重新变回凸的。

flowchart TD
  A[输入特征 x] --> B[线性得分 z 等于 wx 加 b]
  B --> C[Sigmoid 把 z 压到 0 到 1]
  C --> D[属于类别 1 的概率]
  D --> E[交叉熵损失]
  E --> F[梯度下降]

这里为什么不能用平方误差？因为里面套了 sigmoid 之后，平方误差会产生一个布满局部极小值的非凸曲面。交叉熵把凸性还了回来——这才是真正的原因，不是什么约定俗成。

单个样本的损失值得慢慢读一遍：

它对”自信地犯错”的惩罚远远重于”不确定地犯错”。这种不对称就是整个设计的用意。

另外，决策边界在特征空间里仍然是线性的。弯曲的边界来自你构造的特征，不是来自 sigmoid。

五、过拟合，以及三种诚实的应对

症状 训练误差 验证误差 说明 有效的做法
高偏差 高 高，且接近训练误差 模型太简单 加特征、加多项式项、扩大网络、减小 λ
高方差 低 明显更高 模型把数据背下来了 加数据、减特征、增大 λ
刚好 低 接近训练误差 抓住了信号 停止调参

正则化在代价里加上 λ Σ w²，让大权重变得昂贵，拟合因此更平滑。注意 b 不参与正则化——把整个函数上下平移并不会造成过拟合。

第二部分 —— 神经网络，以及怎么知道它行不行

六、神经网络就是逻辑单元堆起来

单个神经元就是逻辑回归；一层是很多个并联；一个网络是很多层串联。它换来的好处是：特征不再需要人工设计。

flowchart TD
  A[输入层 x] --> B[隐藏层 1 ReLU]
  B --> C[隐藏层 2 ReLU]
  C --> D[输出层]
  D --> E[二分类用 Sigmoid]
  D --> F[多分类用 Softmax]
  D --> G[回归用线性输出]

前向传播就是把这张图写下来：每一层拿到上一层的激活值，做 W a + b，再过一个非线性。

七、怎么选激活函数，以及那个数值陷阱

位置 用什么 为什么
隐藏层 ReLU 只有一侧是平的，梯度能穿过深层
输出层，二分类 Sigmoid 需要一个概率
输出层，多分类 Softmax 需要一个类别上的分布
输出层，回归 线性 答案可以是任意实数
输出层，非负回归 ReLU 价格、计数、时长

有两件事我是后来才真正搞明白的：

隐藏层绝不能用线性激活。 一堆线性层在代数上会塌缩成一个线性层——深度什么都没换来。

Softmax 需要数值上的小心。 先算 exp(z) 再相除，在 logits 很大时会丢精度。框架提供了 from_logits=True 这条路径，把 softmax 折进损失里计算，数值更稳。用它，同时把输出层保持成线性。

八、数据怎么分，以及每一份是干什么的

flowchart TD
  A[全部有标注数据] --> B[训练集 百分之六十]
  A --> C[交叉验证集 百分之二十]
  A --> D[测试集 百分之二十]
  B --> E[拟合参数 w 和 b]
  C --> F[选模型、选次数、选 lambda]
  D --> G[只报告一个诚实的最终数字]

我花了一段时间才真正接受的一点：只要你用测试集做过任何选择，它就不再是测试集了。 每一次基于某个划分做出的决定，都会泄漏进那个划分。交叉验证集存在的意义，就是让测试集能一直干净到最后一刻。

九、学习曲线

把误差对训练集大小画出来，两种失败模式看起来完全不同。

高偏差 高方差
训练误差 上升后停在高位 一直很低
验证误差 停在接近训练误差的地方 一直远高于训练误差
两条曲线的间距 很小 很大
加更多数据有用吗 没用 有用

这是整门课里最有用的诊断工具，因为它回答的是一个真的要花钱的问题：我该不该再去收集数据？ 如果两条曲线已经收敛，答案就是不该——再多数据也救不了一个本身就太简单的模型。

十、精确率、召回率，与倾斜数据

当一个类别很稀少时，准确率会骗人。如果只有 0.5% 的病人真的患病，那么一个永远预测”没病”的模型准确率高达 99.5%，却毫无用处。

把判定阈值从 0.5 往上调，精确率升、召回率降；往下调则相反。该往哪边调不是一个数学问题——取决于漏掉一个和误报一个哪个代价更大。罕见疾病更看重召回率；会直接删邮件的垃圾过滤器更看重精确率。

F1 用调和平均而不是算术平均，正是因为它拒绝被单个高分骗过去：精确率 1.0、召回率 0.0，F1 是 0，而不是 0.5。

十一、误差分析，以及真正能带来进步的那个循环

flowchart TD
  A[先做一个又快又简单的模型] --> B[在验证集上测一遍]
  B --> C[手工读一百条预测错误的样本]
  C --> D[把错误分成几类]
  D --> E[数一数哪一类最多]
  E --> F[先修最大的那一类]
  F --> B

手工读一百个错误一点也不光鲜，但它是整个流程里性价比最高的一小时。如果一类错误占 4%、另一类占 40%，那么花在前者上的努力基本是浪费的，无论它看起来多有趣。

数据成为瓶颈时的几个相关手段：

  • 数据增强——要用能代表真实变化的扰动。旋转一张照片是现实的，加纯随机噪声通常不是。
  • 数据合成——从零生成样本，比如为 OCR 用各种字体渲染文字。
  • 迁移学习——拿一个在大规模通用数据上训练好的网络，保留浅层，只重训输出层。它之所以有效，是因为浅层学到的边缘和纹理几乎到哪都通用。

十二、决策树：完全不同的一族

没有梯度，也没有权重。树问一连串是非题，每次分裂都选那个能最大程度降低不纯度的问题。

flowchart TD
  A[节点上的全部样本] --> B[遍历每个特征和阈值]
  B --> C[计算信息增益]
  C --> D[保留最好的分裂]
  D --> E[对每个子节点递归]
  E --> F[到达最大深度或纯节点则停止]

熵衡量一个节点有多”混”：所有样本同一类时是 0，对半分时是 1。信息增益等于分裂前的熵减去分裂后的加权熵——所以被选中的那个问题，就是能买到最多确定性的那个。

神经网络 决策树集成
数据类型 图像、音频、文本 表格、结构化数据
迁移学习 可以 不行
训练成本 高 低到中等
可解释性 差 单棵树可读
通常选择 非结构化数据 大多数表格问题

十三、集成：为什么一棵树永远不够

单棵树是不稳定的——改动几个样本，顶层分裂就可能翻转，长出一棵完全不同的树。

方法 下一棵树怎么长出来 效果
Bagging 有放回地重采样，各自独立训练 把不稳定性平均掉
随机森林 在 Bagging 基础上，每次分裂只看随机的一部分特征 让各棵树进一步去相关
提升（XGBoost） 每棵新树重点关注前面那些树做错的样本 直接冲着剩余误差去

XGBoost 在工业界反复出现是有道理的：在表格数据上它快、几乎不用调参，而且通常打得过手搓的网络。

第三部分 —— 没有标签，甚至没有数据集

十四、K-means

flowchart TD
  A[选 K 个初始质心] --> B[把每个点分给最近的质心]
  B --> C[把每个质心移到它那些点的均值]
  C --> D[与上一轮的分配结果比较]
  D --> E[分配有变化：继续迭代]
  E --> B
  D --> F[分配稳定：算法收敛]

两个容易被忽略的点：

它是有代价函数的。 失真度——每个点到自己质心的均方距离——在两个步骤里都会下降，这正是它一定收敛的原因。如果你的实现里它出现上升，那就是有 bug。

初始化很关键。 随机起点可能落进糟糕的局部极小。做法是用不同的随机初始化跑 50 到 1000 次，保留失真度最低的那一次。

怎么选 K：所谓”肘部法”确实存在，但很少真的出现一个干净的拐点。实际中 K 是由这些簇要拿来干什么决定的——T 恤做三个码还是五个码，因为这才是真正要做的决策。

十五、异常检测

给每个特征拟合一个高斯分布，把概率相乘，低于阈值 ε 的就标为异常。

真正让我想明白的一处区别：

异常检测 监督分类
正样本数量 极少，0 到 20 个 很多
未来的正样本 可能和过去的完全不像 和过去的类似
适合 全新的生产故障、欺诈、入侵 垃圾邮件、已知症状的疾病

你没法要求分类器识别一种它从没见过的故障。异常检测只需要建模”正常长什么样”，所以它能应付真正新出现的问题。

两个实践要点：如果某个特征不服从高斯分布，就做变换（log(x)、x^0.5），直到直方图看起来大致像钟形。另外，当一个异常样本以很高的 p(x) 溜过去时，解决办法通常是构造一个新特征把它分开——往往是两个已有特征的比值。

十六、推荐系统

flowchart TD
  A[推荐问题] --> B[协同过滤]
  A --> C[基于内容的过滤]
  B --> D[从评分中同时学出物品特征和用户偏好]
  C --> E[把用户特征和物品特征各自过一个网络]
  D --> F[无法给全新的物品排序]
  E --> G[能处理新物品和新用户]

协同过滤只靠评分矩阵，就能同时学出物品的特征向量和用户的偏好向量。优雅之处正在这里——没有人去标注一部电影的特征是什么，算法自己发明了一套能解释这些评分的表示。

均值归一化比看上去重要得多。训练前先减去每部电影的平均评分，这样一个一条评分都没有的新用户，被预测出来的就是平均分，而不是全部为零。

基于内容的过滤拿已知的用户特征和物品特征，各自过一个网络变成等长的向量，再做点积。因为它用的是真实特征而不是学出来的 id，所以能给一件还没有任何人评过分的物品排序——这正是协同过滤单独解决不了的冷启动问题。

十七、PCA

找出数据变化最大的那些方向，用每个点在这些方向上的位置来描述它，而不是用原始坐标。

flowchart TD
  A[先做归一化和缩放] --> B[找方差最大的那个方向]
  B --> C[再找与它垂直的下一个方向]
  C --> D[把数据投影到前 k 个方向上]
  D --> E[每个样本用更少的数字表示]

课程里给出的诚实定位：PCA 现在主要是一个可视化工具。把 50 个特征压到 2 个、画出来、真的看见结构，这是实打实的用途。用它来加速监督学习曾经很常见，现在基本不需要了——现代优化器处理完整特征集毫无压力。

而且很关键的一点：PCA 不是防过拟合的手段。它在完全不看标签的情况下丢掉信息；真正知道你在预测什么的，是正则化。

十八、强化学习

完全没有带标签的数据集，只有一个奖励信号。

flowchart TD
  A[智能体观察到状态 s] --> B[选择动作 a]
  B --> C[环境给出奖励和新状态]
  C --> D[回报是未来奖励的折扣和]
  D --> E[学习 Q 函数]
  E --> F[策略选择 Q 值最大的动作]
  F --> A

回报不是奖励的简单求和，而是折扣求和：

折扣因子 γ 让”现在拿到的奖励”比”以后拿到同样的奖励”更值钱。它同时保证了一个永不结束的任务里这个和仍然收敛——这才是它在数学上必须存在的原因。

贝尔曼方程是整件事的递归核心：

用话讲：在状态 s 下采取动作 a 的价值，等于你当下立刻拿到的奖励，加上从落到的那个新状态开始、之后都按最优方式行动所能得到的折扣价值。它和编程里的递归是同一种”用自己的更小版本定义自己”的结构——这也是为什么它比符号看上去要好懂得多。

十九、诊断循环

这是我回头看得最多的一部分。一个表现不好的模型并不神秘，它自己就是一棵决策树。

flowchart TD
  A[模型表现不好] --> B[把训练误差和人类水平比较]
  B --> C[差距很大：高偏差]
  B --> D[差距很小：再看验证集]
  D --> E[验证集差很多：高方差]
  C --> F[更大的模型、更多特征、训练更久]
  E --> G[更多数据、正则化、更简单的模型]
  F --> H[重新测量]
  G --> H

收集更多数据能缓解方差，对偏差几乎没有帮助。知道自己面对的是哪一个，能省下好几周。

我从中得到的

这门课不是学最新架构的地方。它教会我的是：任何模型都是表示、目标、优化这三件事的组合，而大多数失败是可以被诊断的，不是玄学。

真正迁移得最远的其实不是某一个算法，而是一个习惯：在跑任何东西之前，先问”什么结果会告诉我这个判断是错的？”几个月后再去读 MM-UNet 那类论文，明显轻松了不少——模块是陌生的，但要问的问题是同一批。
