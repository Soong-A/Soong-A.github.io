Andrew Ng's Machine Learning Specialization — the foundation map

发表于2025-07-06|更新于2026-10-11|English Notes
|浏览量:

Studied summer 2025 · notes tidied up later · 34 min read

中文版：吴恩达机器学习专项课程：一张完整的基础地图

I worked through the DeepLearning.AI Machine Learning Specialization in the summer of 2025, following the Chinese-subtitled Bilibili course, before touching any research code. It is the course I would recommend to myself a year earlier: it refuses to let you treat a model as a black box, and it keeps returning to the same three questions.

These are the notes I actually go back to.

The shape of the whole course

Almost everything in the specialization fits one template. Pick a model, pick a way to measure wrongness, pick a way to reduce it.

flowchart TD
  A[Model f w b] --> B[Cost function J]
  B --> C[Optimiser]
  C --> D[Updated parameters]
  D --> A
  B --> E[Diagnosis: bias or variance]
  E --> F[Change data, features or regularisation]
  F --> A

If I can name those three pieces for any algorithm, I understand it well enough to debug it. If I cannot, I am only reciting its name.

Course Core question What it adds
1 · Supervised Learning How do I fit and evaluate a model? Linear and logistic regression, gradient descent, regularisation
2 · Advanced Algorithms How do I build something more expressive, and know whether it works? Neural networks, Adam, evaluation, decision trees, ensembles
3 · Unsupervised & RL What if there are no labels, or no dataset at all? Clustering, anomaly detection, recommenders, PCA, reinforcement learning

Part I — Supervised learning

1. Linear regression is the whole method in miniature

The model is a weighted sum. The cost is mean squared error. The optimiser is gradient descent.

Two details that were easy to skip and expensive to skip:

  • Feature scaling. If one feature spans 0–2000 and another 0–5, the cost surface becomes a narrow valley and gradient descent zigzags. Normalising is not cosmetic, it changes how many steps you need.
  • The learning rate is diagnosable. If the cost rises, α is too large. If it falls but barely moves, α is too small. Plotting J against iteration is the cheapest debugging tool in the course.

The optimiser never knows whether the answer is good. It only knows which direction makes the cost smaller. Everything about whether the model is right lives in how you defined the cost and the data.

Why the 1/2 in the cost

Purely so the 2 from differentiating the square cancels. It changes nothing about where the minimum sits — only how tidy the gradient looks.

2. Vectorisation, and why the loop disappears

The version with an explicit loop and the version with np.dot compute the same number. They do not run at the same speed.

NumPy hands the work to optimised low-level routines that use the CPU’s parallel instructions. For a tiny model the difference is invisible; at scale it is the difference between minutes and hours. This is also why gradient descent is written as a matrix update rather than a nested loop — the maths is identical, the execution is not.

3. Feature engineering and polynomial fits

A linear model is only linear in its parameters, not in the raw inputs. Square a feature, multiply two together, take a log — and a straight-line model can fit a curve.

That third line is the useful lesson: frontage × depth is area, and area is what actually drives the price. Feature engineering is where domain knowledge enters a model that otherwise has none.

Polynomial features make scaling essential — if size reaches 1000, then size³ reaches a billion, and gradient descent will crawl.

4. Logistic regression: same machinery, different output

Wrap the same wx + b in a sigmoid and it becomes a probability. Swap squared error for cross-entropy and the cost surface becomes convex again.

flowchart TD
  A[Input features x] --> B[Linear score z equals wx plus b]
  B --> C[Sigmoid maps z to 0 to 1]
  C --> D[Probability of class 1]
  D --> E[Cross-entropy loss]
  E --> F[Gradient descent]

Why not squared error here? With a sigmoid inside, squared error produces a non-convex surface full of local minima. Cross-entropy restores convexity — that is the actual reason, not convention.

The loss for a single example is worth reading slowly:

It punishes confident mistakes far harder than uncertain ones. That asymmetry is the whole design.

The decision boundary stays linear in the features. Curved boundaries come from engineered features, not from the sigmoid.

5. Overfitting, and the three honest responses

Symptom Training error Validation error What it means Useful response
High bias High High, close to training Model too simple More features, polynomial terms, bigger network, lower λ
High variance Low Much higher Model memorised the data More data, fewer features, higher λ
Just right Low Close to training Fits the signal Stop tuning

Regularisation adds λ Σ w² to the cost. Large weights become expensive, so the fit stays smoother. Note that b is not regularised — shifting the whole function up or down is not what causes overfitting.

Part II — Neural networks, and knowing whether they work

6. Neural networks are logistic units, stacked

A single neuron is logistic regression. A layer is many of them in parallel. A network is layers in sequence, and what it buys you is that features no longer have to be designed by hand.

flowchart TD
  A[Input layer x] --> B[Hidden layer 1 ReLU]
  B --> C[Hidden layer 2 ReLU]
  C --> D[Output layer]
  D --> E[Sigmoid for binary]
  D --> F[Softmax for multiclass]
  D --> G[Linear for regression]

Forward propagation is just that diagram written down: each layer takes the previous activation, applies W a + b, then a non-linearity.

7. Choosing an activation, and the numerical trap

Layer Use Why
Hidden ReLU Flat on one side only, so gradients survive depth
Output, binary Sigmoid Needs a single probability
Output, multiclass Softmax Needs a distribution over classes
Output, regression Linear The answer can be any real number
Output, non-negative ReLU Prices, counts, durations

Two things I had to learn properly:

Never use a linear activation in hidden layers. A stack of linear layers collapses algebraically into a single linear layer — the depth buys nothing at all.

Softmax needs numerical care. Computing exp(z) then dividing loses precision when the logits are large. Frameworks expose a from_logits=True path that folds the softmax into the loss and stays stable. Use it, and leave the output layer linear.

8. Splitting the data, and what each split is for

flowchart TD
  A[All labelled data] --> B[Training set 60 percent]
  A --> C[Cross-validation set 20 percent]
  A --> D[Test set 20 percent]
  B --> E[Fit the parameters w and b]
  C --> F[Choose the model, degree and lambda]
  D --> G[Report one honest final number]

The point that took me a while: if you use the test set to choose anything, it stops being a test set. Every decision made against a split leaks into it. The cross-validation set exists so the test set can stay untouched until the very end.

9. Learning curves

Plot error against training-set size and the two failure modes look completely different.

High bias High variance
Training error Rises, then plateaus high Stays low
Validation error Plateaus close to training error Stays far above it
Gap between the curves Small Large
Does more data help? No Yes

This is the most useful diagnostic in the course, because it answers a question that costs real money: should I go and collect more data? If the curves have already converged, the answer is no — no amount of extra data fixes a model that is too simple.

10. Precision, recall, and skewed data

Accuracy lies when one class is rare. If 0.5% of patients have a condition, a model that always predicts “no” is 99.5% accurate and completely useless.

Raising the decision threshold above 0.5 raises precision and lowers recall; lowering it does the reverse. Which way to move is not a maths question — it depends on whether a missed case or a false alarm costs more. For a rare disease, recall matters more. For a spam filter that deletes mail, precision does.

F1 is the harmonic rather than arithmetic mean precisely because it refuses to be fooled by one high number: precision 1.0 with recall 0.0 gives F1 = 0, not 0.5.

11. Error analysis, and the loop that actually improves things

flowchart TD
  A[Start with a quick simple model] --> B[Measure on the validation set]
  B --> C[Read a hundred wrong predictions by hand]
  C --> D[Group the errors into categories]
  D --> E[Count which category is largest]
  E --> F[Fix the largest category first]
  F --> B

Manually reading a hundred mistakes is unglamorous, and it is the highest-value hour in the whole workflow. If 4% of errors are one type and 40% are another, effort spent on the first type is essentially wasted no matter how interesting it is.

Related tools for when data is the bottleneck:

  • Data augmentation — distortions that are representative of real variation. Rotating a photo is realistic; adding pure random noise usually is not.
  • Data synthesis — generating examples from scratch, such as rendering text in many fonts for OCR.
  • Transfer learning — take a network trained on a large general dataset, keep the early layers, retrain the output. It works because early layers learn edges and textures that transfer almost everywhere.

12. Decision trees: a different family entirely

No gradients, no weights. A tree asks a sequence of yes/no questions, choosing at each split the question that reduces impurity the most.

flowchart TD
  A[All examples at a node] --> B[Try every feature and threshold]
  B --> C[Measure information gain]
  C --> D[Keep the best split]
  D --> E[Recurse on each child]
  E --> F[Stop at max depth or pure node]

Entropy measures how mixed a node is: 0 when every example shares a label, 1 at an even split. Information gain is the entropy before a split minus the weighted entropy after it — so the chosen question is the one that buys the most certainty.

Neural network Decision tree ensemble
Data type Images, audio, text Tabular, structured
Transfer learning Yes No
Training cost High Low to moderate
Interpretability Poor A single tree is readable
Typical choice Unstructured data Most spreadsheet problems

13. Ensembles: why one tree is never enough

A single tree is unstable — change a few examples and the top split can flip, producing a completely different tree.

Method How it builds the next tree Effect
Bagging Sample the data with replacement, train independently Averages away the instability
Random forest Bagging plus a random feature subset at each split Decorrelates the trees further
Boosting (XGBoost) Each new tree focuses on what the previous ones got wrong Attacks the remaining error directly

XGBoost keeps appearing in practice for a reason: on tabular data it is fast, needs little tuning, and usually beats a hand-rolled network.

Part III — No labels, no dataset

14. K-means

flowchart TD
  A[Pick K initial centroids] --> B[Assign each point to the nearest centroid]
  B --> C[Move each centroid to the mean of its points]
  C --> D[Compare the new assignments with the previous round]
  D --> E[Assignments changed: repeat]
  E --> B
  D --> F[Assignments stable: converged]

Two things that are easy to miss:

It has a cost function. The distortion — mean squared distance from each point to its assigned centroid — decreases on both steps, which is why it always converges. If your implementation ever shows it rising, there is a bug.

Initialisation matters. Random starts can land in a bad local minimum. The fix is to run it 50–1000 times from different random initialisations and keep the run with the lowest distortion.

Choosing K: the “elbow method” exists but rarely shows a clean elbow. In practice K is chosen by what the clusters are for — three T-shirt sizes or five, because that is the actual decision being made.

15. Anomaly detection

Fit a Gaussian to each feature, multiply the probabilities, and flag anything below a threshold ε.

The distinction that finally landed:

Anomaly detection Supervised classification
Positive examples Very few, 0–20 Many
Future positives May look nothing like past ones Look like past ones
Good for Novel manufacturing faults, fraud, intrusion Spam, disease from known symptoms

You cannot ask a classifier to recognise a failure mode it has never seen. Anomaly detection only has to model normal, which is why it copes with genuinely new failures.

Two practical notes. If a feature is not Gaussian, transform it (log(x), x^0.5) until the histogram looks roughly bell-shaped. And when an anomaly slips through with a high p(x), the fix is usually a new feature that separates it — often a ratio of two existing ones.

16. Recommender systems

flowchart TD
  A[Recommendation problem] --> B[Collaborative filtering]
  A --> C[Content-based filtering]
  B --> D[Learn item features and user preferences together from ratings]
  C --> E[Push user and item features through two networks]
  D --> F[Cannot rank a brand new item]
  E --> G[Handles new items and new users]

Collaborative filtering learns both the item feature vectors and the user preference vectors simultaneously, from the ratings matrix alone. That is the elegant part — nobody labels what a film’s features are; the algorithm invents a representation that explains the ratings.

Mean normalisation matters more than it looks. Subtract each film’s mean rating before training, and a brand-new user with no ratings gets predicted the average rather than zero for everything.

Content-based filtering takes known user features and item features, pushes each through its own network into vectors of the same length, and takes the dot product. Because it uses real features rather than learned ids, it can rank an item nobody has rated yet — the cold start problem collaborative filtering cannot solve alone.

17. PCA

Find the directions in which the data varies most, and describe each point by its position along those directions instead of its original coordinates.

flowchart TD
  A[Normalise and scale the features] --> B[Find the axis of greatest variance]
  B --> C[Find the next axis at right angles]
  C --> D[Project onto the first k axes]
  D --> E[Fewer numbers per example]

The honest framing from the course: PCA is mostly a visualisation tool now. Compressing 50 features to 2 so you can plot them and actually see structure is a real use. Using it to speed up supervised learning used to be common and largely is not any more — modern optimisers handle the full feature set fine.

Crucially, PCA is not a way to prevent overfitting. It discards information without ever looking at the labels; regularisation is the tool that is actually aware of what you are predicting.

18. Reinforcement learning

No labelled dataset at all — only a reward signal.

flowchart TD
  A[Agent observes state s] --> B[Chooses action a]
  B --> C[Environment returns reward and new state]
  C --> D[Return is the discounted sum of future rewards]
  D --> E[Learn Q of s and a]
  E --> F[Policy picks the action with the highest Q]
  F --> A

The return is not the sum of rewards but the discounted sum:

The discount factor γ makes a reward now worth more than the same reward later. It also keeps the sum finite for a task that never ends, which is the mathematical reason it has to be there at all.

The Bellman equation is the recursive heart of it:

In words: the value of taking action a in state s is the reward you get right now, plus the discounted value of behaving optimally from wherever you land. It is the same “define it in terms of a smaller version of itself” structure as recursion in programming — which is why it clicked faster than the notation suggested it would.

19. The diagnosis loop

This is the part I return to most often. A model that underperforms is not a mystery; it is a decision tree of its own.

flowchart TD
  A[Model performs badly] --> B[Compare training error to human level]
  B --> C[Gap is large: high bias]
  B --> D[Gap is small: check validation]
  D --> E[Validation much worse: high variance]
  C --> F[Bigger model, more features, train longer]
  E --> G[More data, regularisation, simpler model]
  F --> H[Re-measure]
  G --> H

Collecting more data helps variance and does almost nothing for bias. Knowing which one you have saves weeks.

What I took from it

The specialization is not where you learn the newest architecture. It is where you learn that every model is a triple of representation, objective, optimisation, and that most failures are diagnosable rather than mysterious.

The part that transferred furthest was not any single algorithm — it was the habit of asking “what would tell me I am wrong about this?” before running anything. Reading MM-UNet papers a few months later was noticeably easier because of it: the modules were unfamiliar, but the questions were the same ones.
